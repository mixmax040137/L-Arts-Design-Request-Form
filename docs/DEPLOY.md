ฝ่ายสื่อสารองค์กร คณะศิลปศาสตร์ มหาวิทยาลัยธรรมศาสตร์

> ติดตั้งครั้งเดียวใช้เวลาประมาณ 20–30 นาที **ต้องทำด้วยบัญชี pr@arts.tu.ac.th เท่านั้น**
> เพราะระบบจะสร้าง Google Sheets, โฟลเดอร์ Drive และส่งอีเมลในนามบัญชีนี้

## ขั้นตอนที่ 1 — สร้างโปรเจกต์ Apps Script

1. เข้าสู่ระบบ Google ด้วยบัญชี **pr@arts.tu.ac.th**
2. เปิด <https://script.google.com/home> แล้วกด **New project**
3. ตั้งชื่อโปรเจกต์ว่า `ระบบขอรับบริการออกแบบสื่อ - ฝ่ายสื่อสารองค์กร`
4. ไปที่ **Project Settings** (ไอคอนเฟือง) แล้วติ๊ก
   ☑ **Show "appsscript.json" manifest file in editor**

## ขั้นตอนที่ 2 — นำโค้ดขึ้นโปรเจกต์

### วิธี ก (แนะนำ) ใช้ clasp — เร็วและไม่มีพลาด

ต้องมี Node.js เวอร์ชัน 18 ขึ้นไปบนเครื่อง

**ก.1 เปิดใช้ Apps Script API (ทำครั้งเดียวต่อบัญชี)**

ล็อกอินเบราว์เซอร์ด้วย **pr@arts.tu.ac.th** แล้วเปิด
<https://script.google.com/home/usersettings> → เปิดสวิตช์ **Google Apps Script API** เป็น **On**
หากข้ามขั้นตอนนี้ `clasp push` จะขึ้น error `User has not enabled the Apps Script API`

**ก.2 ติดตั้ง clasp และเข้าสู่ระบบ**

```bash
npm install -g @google/clasp@2      # ตรึงรุ่น 2.x ซึ่งคำสั่งตรงกับคู่มือนี้
clasp --version
clasp login                          # เบราว์เซอร์จะเปิดขึ้น ให้เลือกบัญชี pr@arts.tu.ac.th
```

> **สำคัญ** หน้าเลือกบัญชีจะแสดงทุกบัญชีที่ล็อกอินอยู่ในเบราว์เซอร์
> ต้องเลือก **pr@arts.tu.ac.th** เท่านั้น หากเผลอเลือกผิด ให้รัน `clasp logout` แล้ว `clasp login` ใหม่

**ก.3 ผูกโฟลเดอร์โค้ดเข้ากับโปรเจกต์**

คัดลอก **Script ID** จาก Apps Script → **Project Settings** → หัวข้อ *IDs* → ช่อง *Script ID*
แล้วสร้างไฟล์ `.clasp.json` ไว้ใน **โฟลเดอร์ `apps-script/`** (ไม่ใช่รากโปรเจกต์)

```json
{
  "scriptId": "วาง Script ID ที่คัดลอกมาตรงนี้",
  "rootDir": "."
}
```

> อย่าใช้ `clasp clone` เพราะจะดาวน์โหลดไฟล์จากเซิร์ฟเวอร์มาทับ `appsscript.json` ของเรา
> การสร้าง `.clasp.json` เองปลอดภัยกว่าและได้ผลเหมือนกัน
> ไฟล์นี้อยู่ใน `.gitignore` แล้ว เพราะเป็นค่าเฉพาะเครื่อง ไม่ต้อง commit

**ก.4 อัปโหลดโค้ด**

```bash
cd apps-script
clasp push -f
clasp open           # เปิดโปรเจกต์ในเบราว์เซอร์เพื่อตรวจสอบ
```

`-f` คือบังคับเขียนทับและลบไฟล์ในเซิร์ฟเวอร์ที่ไม่มีในเครื่อง (เช่น `Code.gs` ที่ติดมากับโปรเจกต์ใหม่)
เมื่อสำเร็จจะขึ้นข้อความ `Pushed 18 files.` ครบทั้ง manifest 1 ไฟล์ สคริปต์ 11 ไฟล์ และ HTML 6 ไฟล์

## ขั้นตอนที่ 3 — ติดตั้งระบบ

1. ในตัวแก้ไข Apps Script เลือกฟังก์ชัน **`setupSystem`** จากเมนูดรอปดาวน์ด้านบน แล้วกด **Run**
2. ครั้งแรกจะขึ้นหน้าขออนุญาต ให้กด **Review permissions** → เลือกบัญชี **pr@arts.tu.ac.th**
   → หากขึ้น "Google hasn't verified this app" ให้กด **Advanced** → **Go to … (unsafe)** → **Allow**
   (ปลอดภัย เพราะเป็นสคริปต์ที่หน่วยงานเขียนเองและรันในบัญชีของหน่วยงานเอง)
3. เมื่อรันเสร็จ เปิด **Execution log** จะเห็นสรุปการติดตั้งและลิงก์ของฐานข้อมูลกับโฟลเดอร์

ระบบจะสร้างให้อัตโนมัติ
- **Google Sheets** ชื่อ `L-Arts Design Request — ฐานข้อมูล` มี 8 ชีต
  (`Requests`, `Deliverables`, `Attachments`, `Revisions`, `Timeline`, `Users`, `Settings`, `Counters`)
- **โฟลเดอร์ Drive** `Design Request System` และโฟลเดอร์ย่อย `คำขอรับบริการ (Jobs)` กับ `คลังผลงาน (Asset Library)`
- **ทริกเกอร์เบื้องหลัง 2 ตัว** — `workerTick` ทุก 5 นาที และ `dailyReminder` ทุกวัน 08:00 น.

> เรียก `setupSystem` ซ้ำได้เสมอ ระบบจะไม่สร้างของซ้ำและไม่ลบข้อมูลเดิม

## ขั้นตอนที่ 4 — สร้างบัญชีเจ้าหน้าที่

ในตัวแก้ไข Apps Script เปิดไฟล์ `03_Setup` แล้วรันคำสั่งนี้ในกล่องฟังก์ชัน
(วิธีง่ายที่สุดคือแก้บรรทัดชั่วคราวแล้วกด Run หรือใช้ช่อง Execute ของ clasp)

```javascript
function ติดตั้งบัญชีแรก() {
  createAdmin('pr@arts.tu.ac.th', 'ธิติวุฒิ บุญแก้ว', 'ตั้งรหัสผ่านที่นี่');
}
```

- รหัสผ่านต้องยาวอย่างน้อย 8 ตัวอักษร
- ระบบเก็บรหัสผ่านเป็นค่าแฮชแบบวนซ้ำ 2,000 รอบพร้อม salt **ไม่เก็บรหัสผ่านจริง**
- เพิ่มเจ้าหน้าที่คนอื่นภายหลังได้จากหน้า **ตั้งค่า → บัญชีเจ้าหน้าที่** ในเว็บแอป
- ลบฟังก์ชันชั่วคราวนี้ทิ้งหลังใช้เสร็จ เพื่อไม่ให้รหัสผ่านค้างอยู่ในโค้ด

## ขั้นตอนที่ 5 — เปิดใช้ AI สรุป Design Brief (ทางเลือก)

ถ้าข้ามขั้นตอนนี้ ระบบยังทำงานได้ครบทุกอย่าง เพียงแต่ Design Brief จะสรุปด้วยสูตรสำเร็จแทน AI

1. สมัครและสร้าง API key ที่ <https://console.anthropic.com>
2. ในตัวแก้ไข Apps Script รันคำสั่ง

```javascript
function ตั้งค่าเอไอ() {
  setAnthropicApiKey('sk-ant-xxxxxxxxxxxxxxxx');
}
```

3. ลบฟังก์ชันชั่วคราวทิ้งหลังรันเสร็จ (กุญแจถูกเก็บใน Script Properties แล้ว ไม่ต้องเก็บในโค้ด)

ระบบใช้โมเดล `claude-opus-5` และบังคับให้ตอบกลับเป็น JSON ตามโครงสร้างที่กำหนด
เปลี่ยนโมเดลได้ที่หน้า **ตั้งค่า → โมเดล AI ที่ใช้**

**ค่าใช้จ่ายโดยประมาณ** คำขอหนึ่งใบใช้ราว 1,000–1,500 token ขาเข้า และ 400–600 token ขาออก
คิดเป็นประมาณ 0.5–0.7 บาทต่อคำขอ (100 คำขอต่อปีประมาณ 50–70 บาท)

## ขั้นตอนที่ 6 — เผยแพร่เป็นเว็บแอป

1. กด **Deploy** → **New deployment**
2. เลือกชนิด (ไอคอนเฟือง) → **Web app**
3. ตั้งค่าดังนี้

| ช่อง | ค่าที่ต้องเลือก |
|---|---|
| Description | `เวอร์ชัน 1.0` |
| Execute as | **Me (pr@arts.tu.ac.th)** |
| Who has access | **Anyone** |

> **ต้องเลือก Anyone** เพื่อให้ผู้ขอรับบริการยื่นคำขอได้โดยไม่ต้องล็อกอิน Google
> ความปลอดภัยของหน้าเจ้าหน้าที่ใช้ระบบรหัสผ่านและ token ของระบบเอง ไม่ได้พึ่งการล็อกอิน Google
> หากนโยบายมหาวิทยาลัยไม่อนุญาต ให้เลือก **Anyone within Thammasat University** แทน
> (ผู้ขอรับบริการจะต้องล็อกอินบัญชี @tu.ac.th ก่อนใช้งาน)

4. กด **Deploy** แล้วคัดลอก **Web app URL** ที่ได้ เช่น
   `https://script.google.com/macros/s/AKfycb.../exec`
5. **รัน `setupSystem` อีกครั้ง** เพื่อให้ระบบบันทึก URL นี้ไว้ใช้สร้างลิงก์ในอีเมล

## ขั้นตอนที่ 7 — ตรวจรับระบบก่อนใช้งานจริง

ทำตามรายการนี้ให้ครบก่อนประกาศใช้

- [ ] เปิด Web app URL แล้วเห็นหน้าแรกพร้อมการ์ด 4 ใบ
- [ ] กด **ยื่นคำขอออกแบบ** กรอกข้อมูลทดสอบให้ครบ 3 ขั้นตอนแล้วส่งได้
- [ ] ได้รับอีเมลยืนยันพร้อมเลขที่คำขอรูปแบบ `DR-2569-0001`
- [ ] คลิกลิงก์ **ติดตามสถานะงาน** ในอีเมลแล้วเปิดหน้าติดตามได้ทันที
- [ ] ตรวจสอบว่าโฟลเดอร์งานถูกสร้างใน Drive และไฟล์แนบอยู่ครบ
- [ ] รอไม่เกิน 5 นาที แล้วเปิดหน้าเจ้าหน้าที่ ตรวจว่ามี Design Brief ปรากฏขึ้น
- [ ] เข้าสู่ระบบเจ้าหน้าที่ เปลี่ยนสถานะเป็น *อยู่ระหว่างออกแบบ* → *รอตรวจร่าง* (ใส่ลิงก์ร่าง)
- [ ] ผู้ขอรับบริการได้รับอีเมลแจ้งทุกครั้งที่สถานะเปลี่ยน
- [ ] ทดสอบกด **แจ้งจุดที่ต้องแก้ไข** ในหน้าติดตาม แล้วสถานะเปลี่ยนเป็น *อยู่ระหว่างแก้ไข*
- [ ] อัปโหลดไฟล์ส่งมอบแล้วเปลี่ยนสถานะเป็น *ส่งมอบแล้ว* ผู้ขอได้รับลิงก์ไฟล์ทางอีเมล
- [ ] แดชบอร์ดแสดงตัวเลขถูกต้อง
- [ ] ลบข้อมูลทดสอบออกจาก Google Sheets (ลบแถวใน `Requests`, `Deliverables`, `Timeline`)

## การใช้งานประจำวัน

### ผู้ขอรับบริการ

1. เปิด Web app URL → **ยื่นคำขอออกแบบ**
2. กรอก 3 ขั้นตอน: ข้อมูลผู้ขอ → รายละเอียดงาน → แนบไฟล์และยืนยัน
3. รับอีเมลยืนยันพร้อมเลขที่คำขอและลิงก์ติดตาม
4. เมื่อได้รับแจ้งว่า *รอตรวจร่าง* ให้เปิดลิงก์ร่าง แล้วกด **อนุมัติ** หรือ **แจ้งจุดที่ต้องแก้ไข**
5. เมื่อสถานะเป็น *ส่งมอบแล้ว* ดาวน์โหลดไฟล์จากลิงก์ในอีเมลหรือหน้าติดตาม

### เจ้าหน้าที่

1. เปิด Web app URL → **สำหรับเจ้าหน้าที่** → เข้าสู่ระบบ
2. แท็บ **คิวงาน** เรียงคำขอใหม่อยู่บนสุด สีแดงคือเกินกำหนด
3. คลิกแถวเพื่อเปิดรายละเอียด จะเห็น
   - **Design Brief** ที่ AI สรุปให้ พร้อมรายการ *ข้อมูลที่ยังขาด* สำหรับสอบถามในคราวเดียว
   - ข้อมูลดิบจากแบบฟอร์ม ไฟล์แนบ ประวัติการแก้ไข และไทม์ไลน์
4. ปุ่มเปลี่ยนสถานะจะแสดงเฉพาะสถานะที่เปลี่ยนไปได้จริง ระบบส่งอีเมลแจ้งผู้ขอให้อัตโนมัติ
5. แท็บ **แดชบอร์ด** ใช้ประกอบรายงานประจำปี แท็บ **คลังผลงาน** ใช้ค้นงานเก่า

| Design Brief ขึ้นว่าสรุปอัตโนมัติเสมอ | ยังไม่ได้ตั้ง API key หรือ key ผิด ดูรายละเอียดในชีต `Timeline` ที่รายการ `BRIEF_FALLBACK` |
| อัปโหลดไฟล์ไม่ผ่าน | ไฟล์เกิน 10 MB หรือนามสกุลไม่อยู่ในรายการที่อนุญาต แก้ได้ที่หน้า **ตั้งค่า** |
| เจ้าหน้าที่เข้าระบบไม่ได้ | กรอกรหัสผิดเกิน 5 ครั้งระบบจะล็อก 15 นาที หรือใช้ `createAdmin` ตั้งรหัสใหม่ |
| แก้โค้ดแล้วเว็บไม่เปลี่ยน | ต้องกด **Deploy → Manage deployments → แก้ไข → Version: New version** ทุกครั้ง |
| `clasp push` ขึ้น `User has not enabled the Apps Script API` | ยังไม่ได้เปิดสวิตช์ที่ <https://script.google.com/home/usersettings> (ขั้นตอน ก.1) รอ 1–2 นาทีหลังเปิดแล้วลองใหม่ |
| `clasp push` ขึ้น `Script ID not found` หรือ `Requested entity was not found` | Script ID ผิด หรือ clasp ล็อกอินอยู่คนละบัญชีกับเจ้าของโปรเจกต์ ตรวจด้วย `clasp login --status` |
| Windows ขึ้น `clasp.ps1 cannot be loaded because running scripts is disabled` | เปิด PowerShell แบบ Administrator แล้วรัน `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` หรือใช้ `clasp.cmd push -f` แทน |
| `clasp` ไม่รู้จักคำสั่ง (command not found) | โฟลเดอร์ global bin ของ npm ไม่อยู่ใน PATH ใช้ `npx @google/clasp@2 push -f` แทนได้ |

## การสำรองข้อมูลและการดูแลรักษา

- **รายเดือน** เปิด Google Sheets ฐานข้อมูล → `File` → `Make a copy` เก็บไว้ในโฟลเดอร์สำรอง
- **รายปีงบประมาณ** ใช้แท็บ **แดชบอร์ด** และปุ่ม **ส่งออก CSV** ทำรายงานผลการปฏิบัติงาน
- ตัวนับเลขที่คำขอรีเซ็ตอัตโนมัติทุกปี พ.ศ. (`DR-2569-0001` → `DR-2570-0001`)
- ห้ามแก้หัวตารางในชีตด้วยมือ ระบบอ่านข้อมูลตามชื่อคอลัมน์
  หากต้องเพิ่มคอลัมน์ ให้แก้ที่ `COLUMNS` ใน `00_Config.gs` แล้วรัน `setupSystem` ใหม่
- ตรวจสถานะระบบได้ทุกเมื่อโดยรันฟังก์ชัน `checkSystem` แล้วดู Execution log

```bash
npm test
```

ชุดทดสอบจำลอง Google Apps Script ทั้งหมด (Sheets, Drive, Gmail, Properties, Cache, Lock,
Triggers และ Claude API) จึงตรวจได้ทั้งการตรวจสอบข้อมูล การเปลี่ยนสถานะ สิทธิ์การเข้าถึง
รอบการแก้ไข การส่งอีเมล และการเรียก Claude API **ควรรันให้ผ่านทุกครั้งก่อนนำโค้ดขึ้นระบบจริง**
