ฝ่ายสื่อสารองค์กร คณะศิลปศาสตร์ มหาวิทยาลัยธรรมศาสตร์

> ติดตั้งครั้งเดียวใช้เวลาประมาณ 10–20 นาที **ต้องทำด้วยบัญชี pr@arts.tu.ac.th เท่านั้น**
> เพราะระบบจะสร้าง Google Sheets, โฟลเดอร์ Drive และส่งอีเมลในนามบัญชีนี้

## ทางลัด — ติดตั้งด้วยคำสั่งเดียว

ถ้ามี Node.js 18 ขึ้นไปบนเครื่องแล้ว ใช้สคริปต์ติดตั้งได้เลย ไม่ต้องทำขั้นตอนที่ 1–5 ด้านล่าง

**macOS / Linux**
```bash
git clone https://github.com/mixmax040137/L-Arts-Design-Request-Form.git
cd L-Arts-Design-Request-Form
git checkout claude/stock-management-system-sujhgs
./setup.sh
```

**Windows (PowerShell)**
```powershell
git clone https://github.com/mixmax040137/L-Arts-Design-Request-Form.git
cd L-Arts-Design-Request-Form
git checkout claude/stock-management-system-sujhgs
.\setup.ps1
```

สคริปต์จะตรวจ Node.js → เข้าสู่ระบบ Google → สร้างโปรเจกต์ Apps Script → อัปโหลดโค้ดครบทุกไฟล์
เหลือให้ทำเองแค่ **กด Deploy ในเบราว์เซอร์** แล้ว **เปิด URL ที่ได้** เท่านั้น
(สองอย่างนี้ Google บังคับให้มีคนกดจริง อัตโนมัติแทนไม่ได้)

ก่อนรันสคริปต์ ต้องเปิด **Apps Script API** ก่อนหนึ่งครั้งตามขั้นตอนที่ 1 ด้านล่าง

> ถ้าสคริปต์ใช้ไม่ได้ด้วยเหตุใดก็ตาม ให้ทำตามขั้นตอนที่ 1–6 ทีละข้อ ได้ผลเหมือนกัน

## ขั้นตอนที่ 1 — เปิด Apps Script API (ทำครั้งเดียวต่อบัญชี)

**ข้ามข้อนี้ไม่ได้** ถ้าไม่ทำ `clasp push` จะฟ้อง `User has not enabled the Apps Script API`

1. เปิดเบราว์เซอร์ ล็อกอินด้วย **pr@arts.tu.ac.th**
2. ไปที่ <https://script.google.com/home/usersettings>
3. เปิดสวิตช์ **Google Apps Script API** เป็น **On**

> ถ้าสวิตช์เป็นสีเทากดไม่ได้ แปลว่าผู้ดูแล Google Workspace ของมหาวิทยาลัยปิดไว้
> ต้องแจ้งฝ่าย IT เปิดให้ หรือใช้วิธีคัดลอกไฟล์ด้วยมือ (ขั้นตอนที่ 3 วิธี ข)

## ขั้นตอนที่ 2 — สร้างโปรเจกต์ Apps Script

ถ้าใช้ `setup.sh` หรือ `setup.ps1` สคริปต์จะสร้างให้เอง **ข้ามไปขั้นตอนที่ 6 ได้เลย**

1. เข้าสู่ระบบ Google ด้วยบัญชี **pr@arts.tu.ac.th**
2. เปิด <https://script.google.com/home> แล้วกด **New project**
3. ตั้งชื่อโปรเจกต์ว่า `ระบบขอรับบริการออกแบบสื่อ - ฝ่ายสื่อสารองค์กร`
4. ไปที่ **Project Settings** (ไอคอนเฟือง) แล้วติ๊ก
   ☑ **Show "appsscript.json" manifest file in editor**
5. เลื่อนลงหาหัวข้อ **IDs** แล้วคัดลอก **Script ID** เก็บไว้

## ขั้นตอนที่ 3 — นำโค้ดขึ้นโปรเจกต์

### วิธี ก ใช้ clasp

```bash
npm install -g @google/clasp@2      # ตรึงรุ่น 2.x ซึ่งคำสั่งตรงกับคู่มือนี้
clasp login                          # เบราว์เซอร์จะเปิดขึ้น ให้เลือกบัญชี pr@arts.tu.ac.th
clasp login --status                 # ตรวจว่าเป็นบัญชีที่ถูกต้อง
```

> **สำคัญ** หน้าเลือกบัญชีจะแสดงทุกบัญชีที่ล็อกอินอยู่ในเบราว์เซอร์
> ต้องเลือก **pr@arts.tu.ac.th** เท่านั้น หากเผลอเลือกผิด ให้รัน `clasp logout` แล้ว `clasp login` ใหม่

สร้างไฟล์ `.clasp.json` ไว้ใน **โฟลเดอร์ `apps-script/`** (ไม่ใช่รากโปรเจกต์)

```json
{
  "scriptId": "วาง Script ID ที่คัดลอกมาตรงนี้",
  "rootDir": "."
}
```

> อย่าใช้ `clasp clone` เพราะจะดาวน์โหลดไฟล์จากเซิร์ฟเวอร์มาทับ `appsscript.json` ของเรา
> ซึ่งเก็บ OAuth scopes ที่ระบบต้องใช้ การสร้าง `.clasp.json` เองปลอดภัยกว่าและได้ผลเหมือนกัน
> ไฟล์นี้อยู่ใน `.gitignore` แล้ว เพราะเป็นค่าเฉพาะเครื่อง ไม่ต้อง commit

จากนั้นอัปโหลด

```bash
cd apps-script
clasp push -f
clasp open           # เปิดโปรเจกต์ในเบราว์เซอร์เพื่อตรวจสอบ
```

`-f` คือบังคับเขียนทับและลบไฟล์ในเซิร์ฟเวอร์ที่ไม่มีในเครื่อง (เช่น `Code.gs` ที่ติดมากับโปรเจกต์ใหม่)
เมื่อสำเร็จจะขึ้น `Pushed 18 files.` ครบทั้ง manifest 1 ไฟล์ สคริปต์ 11 ไฟล์ และ HTML 6 ไฟล์

### วิธี ข คัดลอกด้วยมือ — ใช้ไฟล์รวมในโฟลเดอร์ `dist/`

ถ้าใช้ Terminal ไม่ได้ ให้คัดลอกจากโฟลเดอร์ **`dist/`** ซึ่งรวมไฟล์ `.gs` ทั้ง 11 ไฟล์
ให้เหลือไฟล์เดียว จึงคัดลอกแค่ **8 ไฟล์** แทนที่จะเป็น 18 ไฟล์

> ⚠️ อย่านำ `setup.sh` หรือ `setup.ps1` ไปวางใน Apps Script
> สองไฟล์นั้นเป็นสคริปต์สำหรับรันบน Terminal ของเครื่องตัวเอง ไม่ใช่โค้ดของระบบ

| ลำดับ | ชื่อไฟล์ใน Apps Script | ชนิดที่ต้องเลือก | คัดลอกจาก |
|---|---|---|---|
| 1 | `appsscript` | manifest (มีอยู่แล้ว) | `dist/appsscript.json` |
| 2 | `Code` | Script (มีอยู่แล้ว) | `dist/Code.gs` |
| 3 | `page_App` | **HTML** | `dist/page_App.html` |
| 4 | `ui_Style` | **HTML** | `dist/ui_Style.html` |
| 5 | `ui_Script_Core` | **HTML** | `dist/ui_Script_Core.html` |
| 6 | `ui_Script_Form` | **HTML** | `dist/ui_Script_Form.html` |
| 7 | `ui_Script_Track` | **HTML** | `dist/ui_Script_Track.html` |
| 8 | `ui_Script_Admin` | **HTML** | `dist/ui_Script_Admin.html` |

**วิธีทำทีละขั้น**

1. เปิดหน้าไฟล์บน GitHub แล้วกดปุ่ม **Raw** หรือไอคอน **Copy raw file** เพื่อคัดลอกทั้งไฟล์
2. **`appsscript.json`** — คลิกไฟล์ `appsscript.json` ในตัวแก้ไข → กด Ctrl+A → วางทับ → Ctrl+S
   (ถ้าไม่เห็นไฟล์นี้ ให้ไปที่ Project Settings แล้วติ๊ก *Show "appsscript.json" manifest file in editor*)
3. **`Code.gs`** — คลิกไฟล์ `Code.gs` → Ctrl+A → วางทับด้วยเนื้อหาของ `dist/Code.gs` → Ctrl+S
   (ไฟล์นี้ยาวประมาณ 4,000 บรรทัด ให้รอจนวางเสร็จก่อนกดบันทึก)
4. **ไฟล์ HTML อีก 6 ไฟล์** — กด **+** ข้างคำว่า Files → เลือก **HTML** → พิมพ์ชื่อตามตาราง
   (ไม่ต้องพิมพ์ `.html` ระบบเติมให้เอง) → วางเนื้อหา → Ctrl+S

**สำคัญ** ชื่อไฟล์ HTML ทั้ง 6 ไฟล์ต้องสะกดตรงตามตารางเป๊ะ เพราะโค้ดเรียกด้วยชื่อเหล่านี้
ส่วนไฟล์ `.gs` จะตั้งชื่อว่าอะไรก็ได้

> โฟลเดอร์ `dist/` สร้างอัตโนมัติจากซอร์สด้วยคำสั่ง `npm run bundle`
> และมีเทสต์ตรวจทุกครั้งว่าทำงานเหมือนไฟล์แยกทุกประการ

## ขั้นตอนที่ 4 — เผยแพร่เป็นเว็บแอป

1. กด **Deploy** → **New deployment**
2. กดไอคอนเฟืองข้างคำว่า Select type → เลือก **Web app**
3. ตั้งค่าดังนี้

| ช่อง | ค่าที่ต้องเลือก |
|---|---|
| Description | `เวอร์ชัน 1.0` |
| Execute as | **Me (pr@arts.tu.ac.th)** |
| Who has access | **Anyone** |

> **ต้องเลือก Anyone** เพื่อให้ผู้ขอรับบริการยื่นคำขอได้โดยไม่ต้องล็อกอิน Google
> ความปลอดภัยของหน้าเจ้าหน้าที่ใช้ระบบรหัสผ่านและ token ของระบบเอง ไม่ได้พึ่งการล็อกอิน Google
> หากนโยบายมหาวิทยาลัยไม่อนุญาต ให้เลือก **Anyone within Thammasat University** แทน
> (ผู้ขอรับบริการจะต้องล็อกอินบัญชี @tu.ac.th ก่อนใช้งาน)

4. กด **Deploy** จะขึ้นหน้าขออนุญาต ให้กด **Authorize access** → เลือกบัญชี **pr@arts.tu.ac.th**
   → หากขึ้น "Google hasn't verified this app" ให้กด **Advanced** → **Go to … (unsafe)** → **Allow**
   (ปลอดภัย เพราะเป็นสคริปต์ที่หน่วยงานเขียนเองและรันในบัญชีของหน่วยงานเอง)
5. คัดลอก **Web app URL** ที่ได้ เช่น `https://script.google.com/macros/s/AKfycb.../exec`

## ขั้นตอนที่ 5 — เปิด URL แล้วระบบติดตั้งตัวเอง

เปิด Web app URL ที่คัดลอกมาในเบราว์เซอร์ ครั้งแรกจะใช้เวลาราว 20 วินาที เพราะระบบกำลังสร้างให้อัตโนมัติ

- **Google Sheets** ชื่อ `L-Arts Design Request — ฐานข้อมูล` พร้อม 8 ชีต
  (`Requests`, `Deliverables`, `Attachments`, `Revisions`, `Timeline`, `Users`, `Settings`, `Counters`)
- **โฟลเดอร์ Drive** `Design Request System` และโฟลเดอร์ย่อย `คำขอรับบริการ (Jobs)` กับ `คลังผลงาน (Asset Library)`
- **ทริกเกอร์เบื้องหลัง 2 ตัว** — `workerTick` ทุก 5 นาที และ `dailyReminder` ทุกวัน 08:00 น.
- **รหัสติดตั้ง** ซึ่งระบบจะส่งไปที่อีเมล **pr@arts.tu.ac.th** ทันที

จากนั้นหน้าเว็บจะพาไปยังหน้า **ตั้งค่าระบบครั้งแรก** ให้กรอก

| ช่อง | ค่าที่กรอก |
|---|---|
| รหัสติดตั้ง | คัดลอกจากอีเมลที่ระบบเพิ่งส่งมา (หรือกดลิงก์ในอีเมลแล้วระบบกรอกให้เอง) |
| อีเมลผู้ดูแลระบบ | `pr@arts.tu.ac.th` |
| ชื่อ-นามสกุล | ชื่อผู้ดูแลระบบ |
| รหัสผ่าน | อย่างน้อย 8 ตัวอักษร |

กด **สร้างบัญชีและเริ่มใช้งาน** ระบบจะเข้าสู่ระบบให้อัตโนมัติและพาไปหน้าจัดการคำขอ
**รหัสติดตั้งจะถูกยกเลิกทันทีและใช้ซ้ำไม่ได้**

> จะเห็นรหัสติดตั้งและลิงก์สร้างบัญชีอยู่ในนั้น
>
> **ทางเลือกสำหรับผู้ถนัดใช้ตัวแก้ไข** สร้างบัญชีจาก Apps Script ได้เช่นกันด้วย
> `createAdmin('pr@arts.tu.ac.th', 'ชื่อผู้ดูแลระบบ', 'รหัสผ่าน')` แล้วลบฟังก์ชันชั่วคราวทิ้งหลังใช้เสร็จ

## ลิงก์ของระบบ ใครใช้ลิงก์ไหน

ระบบมี **URL เดียว** คือ Web app URL ที่ได้จากขั้นตอนที่ 4
หน้าที่ต่างกันแยกด้วยพารามิเตอร์ท้าย URL เท่านั้น

| ลิงก์ | ใครใช้ | ใช้ทำอะไร |
|---|---|---|
| `.../exec` | **ผู้ขอรับบริการ** (แจกได้เลย) | หน้าแรก ยื่นคำขอ ติดตามสถานะ ดูเงื่อนไขบริการ |
| `.../exec?page=form` | ผู้ขอรับบริการ | เข้าหน้ายื่นคำขอโดยตรง |
| `.../exec?page=track` | ผู้ขอรับบริการ | เข้าหน้าติดตามสถานะโดยตรง |
| `.../exec?page=login` | **เจ้าหน้าที่เท่านั้น** | เข้าสู่ระบบจัดการคิวงาน |
| `.../exec?page=track&job=...&t=...` | ผู้ขอรับบริการรายนั้น | ลิงก์เฉพาะใบที่ระบบส่งไปในอีเมล เปิดแล้วเห็นงานของตัวเองทันที |
| `.../exec?page=setup&k=...` | ผู้ติดตั้งระบบ | **ใช้ได้ครั้งเดียวตอนติดตั้ง** เพื่อสร้างบัญชีผู้ดูแลคนแรก แล้วหมดอายุถาวร |

**การเพิ่มบัญชีผู้ใช้ระบบหลังจากนั้น** ไม่มีลิงก์สาธารณะ ต้องทำจากในระบบเท่านั้น
เข้าสู่ระบบด้วยบัญชีผู้ดูแล → แท็บ **ตั้งค่า** → หัวข้อ **บัญชีเจ้าหน้าที่** → ปุ่ม **เพิ่มบัญชี**
(เฉพาะสิทธิ์ผู้ดูแลระบบเท่านั้น เจ้าหน้าที่ทั่วไปเปิดหน้านี้ไม่ได้)

**ผู้ขอรับบริการไม่ต้องมีบัญชี** และไม่ต้องล็อกอิน Google ใด ๆ ทั้งสิ้น
ระบบยืนยันตัวตนจากเลขที่คำขอคู่กับอีเมลที่ใช้ยื่น หรือจาก token ในลิงก์ที่ส่งไปทางอีเมล

> ลิงก์ทั้งหมดนี้ดูและคัดลอกได้จากในระบบ ที่ **ตั้งค่า → ลิงก์ของระบบ**

**ข้อควรระวังเรื่อง `/dev` กับ `/exec`**
URL ที่ลงท้ายด้วย `/dev` คือเวอร์ชันทดสอบ เปิดได้เฉพาะเจ้าของสคริปต์และแสดงโค้ดล่าสุดเสมอ
**ห้ามแจกลิงก์ `/dev` ให้ผู้ขอรับบริการ** เพราะคนอื่นเปิดไม่ได้ ต้องแจก `/exec` เท่านั้น

## ขั้นตอนที่ 6 — เปิดใช้ AI สรุป Design Brief (ทางเลือก)

ถ้าข้ามขั้นตอนนี้ ระบบยังทำงานได้ครบทุกอย่าง เพียงแต่ Design Brief จะสรุปด้วยสูตรสำเร็จแทน AI

1. สมัครและสร้าง API key ที่ <https://console.anthropic.com>
2. ในเว็บแอป เข้าสู่ระบบเจ้าหน้าที่ → แท็บ **ตั้งค่า** → หัวข้อ **การเชื่อมต่อ AI สรุป Design Brief**
3. วาง API key แล้วกด **บันทึก**

ระบบเก็บคีย์ไว้ใน Script Properties และไม่เคยส่งกลับมาแสดงบนหน้าเว็บอีก
ใช้โมเดล `claude-opus-5` และบังคับให้ตอบกลับเป็น JSON ตามโครงสร้างที่กำหนด
เปลี่ยนโมเดลได้ที่ช่อง **โมเดล AI ที่ใช้** ในหน้าเดียวกัน

**ค่าใช้จ่ายโดยประมาณ** คำขอหนึ่งใบใช้ราว 1,000–1,500 token ขาเข้า และ 400–600 token ขาออก
คิดเป็นประมาณ 0.5–0.7 บาทต่อคำขอ (100 คำขอต่อปีประมาณ 50–70 บาท)

## การอัปเดตระบบเป็นเวอร์ชันใหม่

หลังติดตั้งครั้งแรกแล้ว การอัปเดตทำได้ด้วยคำสั่งเดียว **ไม่ต้องเข้าเบราว์เซอร์อีกเลย**

```bash
./deploy.sh                    # macOS และ Linux
.\deploy.ps1                   # Windows
```

หรือระบุคำอธิบายเวอร์ชันเอง

```bash
./deploy.sh "เพิ่มการแจ้งเตือนผู้ออกแบบ"
```

สคริปต์จะทำให้ตามลำดับ
1. **รันชุดทดสอบก่อน** ถ้าไม่ผ่านจะหยุดทันที ไม่อัปโหลดโค้ดเสีย
2. อัปโหลดโค้ดล่าสุดขึ้นโปรเจกต์ (`clasp push -f`)
3. ออกเวอร์ชันใหม่ทับ deployment เดิม (`clasp deploy -i`) — **URL ของเว็บแอปไม่เปลี่ยน**
   ผู้ใช้เห็นเวอร์ชันใหม่ทันทีเมื่อรีเฟรชหน้า

> ครั้งแรกสุดต้องกด **Deploy → New deployment** ในเบราว์เซอร์หนึ่งครั้งก่อน (ตามขั้นตอนที่ 4)
> หลังจากนั้น `./deploy.sh` จัดการให้ทั้งหมด

**ถ้าใช้วิธีคัดลอกไฟล์ด้วยมือ** ให้คัดลอกไฟล์จาก `dist/` ทับของเดิม แล้วกด
**Deploy → Manage deployments → ไอคอนดินสอ → Version: New version → Deploy**
(อย่ากด *New deployment* เพราะจะได้ URL ใหม่ ทำให้ลิงก์ที่แจกไปแล้วใช้ไม่ได้)

## เปิดลิงก์เว็บแอปไม่ได้ ทำอย่างไร

อาการ: คัดลอก URL จาก Deploy มาเปิดแล้วขึ้นหน้าขออนุญาต เข้าไม่ได้ หรือขึ้นหน้าเปล่า
ไล่ตรวจตามลำดับนี้ ส่วนใหญ่จบที่ข้อ 1 หรือ 2

**1. คัดลอกผิดช่อง** — ในกล่อง *Manage deployments* มี URL อยู่ 2 ช่อง

| ช่อง | หน้าตา | ใช้ได้ไหม |
|---|---|---|
| **Web app → URL** | `.../macros/s/AKfycb.../exec` | ✅ ช่องนี้เท่านั้น |
| Library → URL | `.../macros/library/d/.../2` | ❌ เปิดเป็นหน้าเว็บไม่ได้ |

URL ในกล่องจะถูกตัดด้วย `…` ให้กดปุ่ม **Copy** ใต้หัวข้อ *Web app* อย่าลากเมาส์คลุมเอง

**2. ล็อกอิน Google หลายบัญชีพร้อมกัน** — สาเหตุที่พบบ่อยที่สุด
สังเกตแถบที่อยู่ ถ้าขึ้น `script.google.com/u/1/...` แปลว่ากำลังใช้บัญชีลำดับที่ 2
เวลาเปิดลิงก์ `/exec` เบราว์เซอร์จะเปิดด้วยบัญชีหลัก (`u/0`) ซึ่งอาจไม่มีสิทธิ์

*วิธีทดสอบให้รู้ผลทันที* เปิดลิงก์ `/exec` ใน **หน้าต่างไม่ระบุตัวตน (Incognito)**
- เปิดได้ → เป็นปัญหาหลายบัญชีในเบราว์เซอร์เท่านั้น ระบบไม่มีปัญหา
  แก้โดยออกจากบัญชีอื่นให้เหลือบัญชีเดียว หรือใช้โปรไฟล์เบราว์เซอร์แยก
- เปิดไม่ได้เหมือนกัน → ไปข้อ 3

**3. ตั้งค่าสิทธิ์ของ deployment ผิด**
Deploy → **Manage deployments** → ไอคอนดินสอ → ตรวจว่า

| ช่อง | ต้องเป็น |
|---|---|
| Execute as | **Me** |
| Who has access | **Anyone** |

ถ้าเป็น *Only myself* หรือ *Anyone with Google Account* คนนอกจะเปิดไม่ได้
แก้แล้วต้องกด **Deploy** ซ้ำเพื่อให้มีผล

**4. ใช้ URL ที่ลงท้าย `/dev`** — เปิดได้เฉพาะเจ้าของสคริปต์ ห้ามแจกให้ผู้อื่น

**5. หา URL ที่ถูกต้องไม่เจอเลย** — ในตัวแก้ไข Apps Script เลือกฟังก์ชัน **`showLinks`**
แล้วกด **Run** จากนั้นเปิด **Execution log** ระบบจะพิมพ์ลิงก์ที่ถูกต้องทั้งหมดให้
พร้อมบอกว่ามีบัญชีเจ้าหน้าที่กี่บัญชี มีคำขอกี่รายการ และอีเมลใดได้รับแจ้งเตือนบ้าง

## เปิด Apps Script จากในชีตแล้วเจอโค้ดว่างเปล่า

**เป็นเรื่องปกติ ไม่ใช่ความผิดพลาด** และ **ห้ามวางโค้ดลงในโปรเจกต์นั้น**

สเปรดชีตฐานข้อมูลถูกสร้างขึ้นโดยสคริปต์ จึงไม่ใช่ชีตที่ผูกกับสคริปต์ (ไม่ใช่ container-bound)
เมื่อกด **Extensions → Apps Script** จากในชีต Google จะ **สร้างโปรเจกต์ใหม่ที่ว่างเปล่า**
ชื่อ *Untitled project* ให้เสมอ ซึ่งไม่เกี่ยวข้องกับระบบเลย

โปรเจกต์จริงของระบบชื่อ **ระบบขอรับบริการออกแบบสื่อ - ฝ่ายสื่อสารองค์กร**
เปิดได้จาก <https://script.google.com/home> หรือจากลิงก์ที่ `showLinks` พิมพ์ให้
โปรเจกต์ *Untitled project* ที่เผลอสร้างไว้ ลบทิ้งได้เลยโดยไม่กระทบอะไร
