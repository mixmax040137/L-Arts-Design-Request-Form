# คู่มือติดตั้งระบบขอรับบริการออกแบบสื่อประชาสัมพันธ์

ฝ่ายสื่อสารองค์กร คณะศิลปศาสตร์ มหาวิทยาลัยธรรมศาสตร์

> ติดตั้งครั้งเดียวใช้เวลาประมาณ 10–20 นาที **ต้องทำด้วยบัญชี pr@arts.tu.ac.th เท่านั้น**
> เพราะระบบจะสร้าง Google Sheets, โฟลเดอร์ Drive และส่งอีเมลในนามบัญชีนี้

## ภาพรวมสถาปัตยกรรม

```
ผู้ขอรับบริการ / เจ้าหน้าที่  (เบราว์เซอร์)
              │
              ▼
   Cloudflare (ระบบหลัก)              ← โค้ดชุดเดียวกับ apps-script/ + cloudflare/
   https://design.tu-arts.workers.dev
   ฐานข้อมูลหลักอยู่ใน SQLite ของ Durable Object ตอบเร็วระดับมิลลิวินาที
              │  ส่งทุกการเปลี่ยนแปลงไปสำรองอัตโนมัติ (ทางเดียว ตามลำดับ ลองใหม่เองเมื่อ Google ล่ม)
              ▼
   Google Apps Script Web App (ระบบสำรอง)
              │
      ┌───────┼─────────┬──────────────┐
      ▼       ▼         ▼              ▼
 Google    Google     Gmail        Claude API
 Sheets     Drive    (แจ้งเตือน)   (Cloudflare เรียกเอง)
(สำเนาสำรอง) (ไฟล์งาน)
```

- **Cloudflare เป็นระบบหลัก** ผู้ขอยื่นคำขอและเจ้าหน้าที่ทำงานที่ลิงก์ Cloudflare ทั้งหมด
- **Apps Script เป็นระบบสำรองอัตโนมัติ** ได้รับสำเนาข้อมูลทุกแถวใน Google Sheets ภายในไม่กี่วินาที
  และยังเป็นคนส่งอีเมลกับเก็บไฟล์บน Google Drive ให้ (Cloudflare ไม่มีสิทธิ์เข้า Drive/Gmail ของคณะเอง)
- ลิงก์ Apps Script เดิมที่แจกไปแล้วยังใช้ได้ ระบบพาไปหน้า Cloudflare ให้เอง
- ถ้า Cloudflare มีปัญหา ผู้ดูแลระบบสลับกลับไปใช้ Apps Script ได้ทันที (หัวข้อ *ระบบหลักบน Cloudflare* ด้านล่าง)

ทุกอย่างฝั่ง Google รันด้วยสิทธิ์ของบัญชี **pr@arts.tu.ac.th** ฝั่ง Cloudflare ใช้แผนฟรี
ไม่มีค่าใช้จ่ายเพิ่ม (ยกเว้นค่าใช้ Claude API ซึ่งเป็นทางเลือก)

## ทางลัด — ติดตั้งด้วยคำสั่งเดียว

ถ้ามี Node.js 18 ขึ้นไปบนเครื่องแล้ว ใช้สคริปต์ติดตั้งได้เลย ไม่ต้องทำขั้นตอนที่ 1–5 ด้านล่าง

**macOS / Linux**
```bash
git clone https://github.com/mixmax040137/L-Arts-Design-Request-Form.git
cd L-Arts-Design-Request-Form
git checkout claude/stock-management-system-sujhgs
./setup.sh
```

**Windows (PowerShell)**
```powershell
git clone https://github.com/mixmax040137/L-Arts-Design-Request-Form.git
cd L-Arts-Design-Request-Form
git checkout claude/stock-management-system-sujhgs
.\setup.ps1
```

สคริปต์จะตรวจ Node.js → เข้าสู่ระบบ Google → สร้างโปรเจกต์ Apps Script → อัปโหลดโค้ดครบทุกไฟล์
เหลือให้ทำเองแค่ **กด Deploy ในเบราว์เซอร์** แล้ว **เปิด URL ที่ได้** เท่านั้น
(สองอย่างนี้ Google บังคับให้มีคนกดจริง อัตโนมัติแทนไม่ได้)

ก่อนรันสคริปต์ ต้องเปิด **Apps Script API** ก่อนหนึ่งครั้งตามขั้นตอนที่ 1 ด้านล่าง

> ถ้าสคริปต์ใช้ไม่ได้ด้วยเหตุใดก็ตาม ให้ทำตามขั้นตอนที่ 1–6 ทีละข้อ ได้ผลเหมือนกัน

## ขั้นตอนที่ 2 — สร้างโปรเจกต์ Apps Script

## ขั้นตอนที่ 3 — นำโค้ดขึ้นโปรเจกต์

### วิธี ก ใช้ clasp

```bash
npm install -g @google/clasp@2      # ตรึงรุ่น 2.x ซึ่งคำสั่งตรงกับคู่มือนี้
clasp login                          # เบราว์เซอร์จะเปิดขึ้น ให้เลือกบัญชี pr@arts.tu.ac.th
clasp login --status                 # ตรวจว่าเป็นบัญชีที่ถูกต้อง
```

> **สำคัญ** หน้าเลือกบัญชีจะแสดงทุกบัญชีที่ล็อกอินอยู่ในเบราว์เซอร์
> ต้องเลือก **pr@arts.tu.ac.th** เท่านั้น หากเผลอเลือกผิด ให้รัน `clasp logout` แล้ว `clasp login` ใหม่

สร้างไฟล์ `.clasp.json` ไว้ใน **โฟลเดอร์ `apps-script/`** (ไม่ใช่รากโปรเจกต์)

```json
{
  "scriptId": "วาง Script ID ที่คัดลอกมาตรงนี้",
  "rootDir": "."
}
```

> อย่าใช้ `clasp clone` เพราะจะดาวน์โหลดไฟล์จากเซิร์ฟเวอร์มาทับ `appsscript.json` ของเรา
> ซึ่งเก็บ OAuth scopes ที่ระบบต้องใช้ การสร้าง `.clasp.json` เองปลอดภัยกว่าและได้ผลเหมือนกัน
> ไฟล์นี้อยู่ใน `.gitignore` แล้ว เพราะเป็นค่าเฉพาะเครื่อง ไม่ต้อง commit

จากนั้นอัปโหลด

```bash
cd apps-script
clasp push -f
clasp open           # เปิดโปรเจกต์ในเบราว์เซอร์เพื่อตรวจสอบ
```

`-f` คือบังคับเขียนทับและลบไฟล์ในเซิร์ฟเวอร์ที่ไม่มีในเครื่อง (เช่น `Code.gs` ที่ติดมากับโปรเจกต์ใหม่)
เมื่อสำเร็จจะขึ้น `Pushed 22 files.` ครบทั้ง manifest 1 ไฟล์ สคริปต์ 15 ไฟล์ และ HTML 6 ไฟล์

### วิธี ข คัดลอกด้วยมือ — ใช้ไฟล์รวมในโฟลเดอร์ `dist/`

ถ้าใช้ Terminal ไม่ได้ ให้คัดลอกจากโฟลเดอร์ **`dist/`** ซึ่งรวมไฟล์ `.gs` ทั้ง 15 ไฟล์
ให้เหลือไฟล์เดียว จึงคัดลอกแค่ **8 ไฟล์** แทนที่จะเป็น 22 ไฟล์

> ⚠️ อย่านำ `setup.sh` หรือ `setup.ps1` ไปวางใน Apps Script
> สองไฟล์นั้นเป็นสคริปต์สำหรับรันบน Terminal ของเครื่องตัวเอง ไม่ใช่โค้ดของระบบ

| ลำดับ | ชื่อไฟล์ใน Apps Script | ชนิดที่ต้องเลือก | คัดลอกจาก |
|---|---|---|---|
| 1 | `appsscript` | manifest (มีอยู่แล้ว) | `dist/appsscript.json` |
| 2 | `Code` | Script (มีอยู่แล้ว) | `dist/Code.gs` |
| 3 | `page_App` | **HTML** | `dist/page_App.html` |
| 4 | `ui_Style` | **HTML** | `dist/ui_Style.html` |
| 5 | `ui_Script_Core` | **HTML** | `dist/ui_Script_Core.html` |
| 6 | `ui_Script_Form` | **HTML** | `dist/ui_Script_Form.html` |
| 7 | `ui_Script_Track` | **HTML** | `dist/ui_Script_Track.html` |
| 8 | `ui_Script_Admin` | **HTML** | `dist/ui_Script_Admin.html` |

**วิธีทำทีละขั้น**

1. เปิดหน้าไฟล์บน GitHub แล้วกดปุ่ม **Raw** หรือไอคอน **Copy raw file** เพื่อคัดลอกทั้งไฟล์
2. **`appsscript.json`** — คลิกไฟล์ `appsscript.json` ในตัวแก้ไข → กด Ctrl+A → วางทับ → Ctrl+S
   (ถ้าไม่เห็นไฟล์นี้ ให้ไปที่ Project Settings แล้วติ๊ก *Show "appsscript.json" manifest file in editor*)
3. **`Code.gs`** — คลิกไฟล์ `Code.gs` → Ctrl+A → วางทับด้วยเนื้อหาของ `dist/Code.gs` → Ctrl+S
   (ไฟล์นี้ยาวประมาณ 4,000 บรรทัด ให้รอจนวางเสร็จก่อนกดบันทึก)
4. **ไฟล์ HTML อีก 6 ไฟล์** — กด **+** ข้างคำว่า Files → เลือก **HTML** → พิมพ์ชื่อตามตาราง
   (ไม่ต้องพิมพ์ `.html` ระบบเติมให้เอง) → วางเนื้อหา → Ctrl+S

**สำคัญ** ชื่อไฟล์ HTML ทั้ง 6 ไฟล์ต้องสะกดตรงตามตารางเป๊ะ เพราะโค้ดเรียกด้วยชื่อเหล่านี้
ส่วนไฟล์ `.gs` จะตั้งชื่อว่าอะไรก็ได้

> โฟลเดอร์ `dist/` สร้างอัตโนมัติจากซอร์สด้วยคำสั่ง `npm run bundle`
> และมีเทสต์ตรวจทุกครั้งว่าทำงานเหมือนไฟล์แยกทุกประการ

## ขั้นตอนที่ 4 — เผยแพร่เป็นเว็บแอป

1. กด **Deploy** → **New deployment**
2. กดไอคอนเฟืองข้างคำว่า Select type → เลือก **Web app**
3. ตั้งค่าดังนี้

| ช่อง | ค่าที่ต้องเลือก |
|---|---|
| Description | `เวอร์ชัน 1.0` |
| Execute as | **Me (pr@arts.tu.ac.th)** |
| Who has access | **Anyone** |

> **ต้องเลือก Anyone** เพื่อให้ผู้ขอรับบริการยื่นคำขอได้โดยไม่ต้องล็อกอิน Google
> และเพื่อให้ Cloudflare ส่งข้อมูลมาสำรองได้ (Cloudflare ล็อกอิน Google ไม่ได้)
> ความปลอดภัยของหน้าเจ้าหน้าที่ใช้ระบบรหัสผ่านและ token ของระบบเอง ไม่ได้พึ่งการล็อกอิน Google
> ส่วนการรับข้อมูลจาก Cloudflare ใช้รหัสลับที่ออกตอนจับคู่ คนอื่นส่งข้อมูลเข้ามาไม่ได้

4. กด **Deploy** จะขึ้นหน้าขออนุญาต ให้กด **Authorize access** → เลือกบัญชี **pr@arts.tu.ac.th**
   → หากขึ้น "Google hasn't verified this app" ให้กด **Advanced** → **Go to … (unsafe)** → **Allow**
   (ปลอดภัย เพราะเป็นสคริปต์ที่หน่วยงานเขียนเองและรันในบัญชีของหน่วยงานเอง)
5. คัดลอก **Web app URL** ที่ได้ เช่น `https://script.google.com/macros/s/AKfycb.../exec`

เปิด Web app URL ที่คัดลอกมาในเบราว์เซอร์ ครั้งแรกจะใช้เวลาราว 20 วินาที เพราะระบบกำลังสร้างให้อัตโนมัติ

จากนั้นหน้าเว็บจะพาไปยังหน้า **ตั้งค่าระบบครั้งแรก** ให้กรอก

| ช่อง | ค่าที่กรอก |
|---|---|
| รหัสติดตั้ง | คัดลอกจากอีเมลที่ระบบเพิ่งส่งมา (หรือกดลิงก์ในอีเมลแล้วระบบกรอกให้เอง) |
| อีเมลผู้ดูแลระบบ | `pr@arts.tu.ac.th` |
| ชื่อ-นามสกุล | ชื่อผู้ดูแลระบบ |
| รหัสผ่าน | อย่างน้อย 8 ตัวอักษร |

กด **สร้างบัญชีและเริ่มใช้งาน** ระบบจะเข้าสู่ระบบให้อัตโนมัติและพาไปหน้าจัดการคำขอ
**รหัสติดตั้งจะถูกยกเลิกทันทีและใช้ซ้ำไม่ได้**

> **ถ้าไม่ได้รับอีเมล** เปิด Apps Script → เลือกฟังก์ชัน `setupSystem` → กด **Run** → ดู **Execution log**
> จะเห็นรหัสติดตั้งและลิงก์สร้างบัญชีอยู่ในนั้น
>
> **ทางเลือกสำหรับผู้ถนัดใช้ตัวแก้ไข** สร้างบัญชีจาก Apps Script ได้เช่นกัน โดยเพิ่มฟังก์ชันชั่วคราว
> `function tmpAdmin() { createAdmin_('pr@arts.tu.ac.th', 'ชื่อผู้ดูแลระบบ', 'รหัสผ่าน'); }`
> เลือก `tmpAdmin` แล้วกด **Run** จากนั้น **ลบฟังก์ชันชั่วคราวทิ้งทันที**
> (`createAdmin_` ลงท้ายด้วย `_` จึงเรียกจากหน้าเว็บไม่ได้ ต้องเรียกผ่านฟังก์ชันชั่วคราวเท่านั้น)

## ลิงก์ของระบบ ใครใช้ลิงก์ไหน

ระบบมี **URL เดียว** คือ Web app URL ที่ได้จากขั้นตอนที่ 4
หน้าที่ต่างกันแยกด้วยพารามิเตอร์ท้าย URL เท่านั้น

| ลิงก์ | ใครใช้ | ใช้ทำอะไร |
|---|---|---|
| `.../exec` | **ผู้ขอรับบริการ** (แจกได้เลย) | หน้าแรก ยื่นคำขอ ติดตามสถานะ ดูเงื่อนไขบริการ |
| `.../exec?page=form` | ผู้ขอรับบริการ | เข้าหน้ายื่นคำขอโดยตรง |
| `.../exec?page=track` | ผู้ขอรับบริการ | เข้าหน้าติดตามสถานะโดยตรง |
| `.../exec?page=login` | **เจ้าหน้าที่เท่านั้น** | เข้าสู่ระบบจัดการคิวงาน |
| `.../exec?page=track&job=...&t=...` | ผู้ขอรับบริการรายนั้น | ลิงก์เฉพาะใบที่ระบบส่งไปในอีเมล เปิดแล้วเห็นงานของตัวเองทันที |
| `.../exec?page=setup&k=...` | ผู้ติดตั้งระบบ | **ใช้ได้ครั้งเดียวตอนติดตั้ง** เพื่อสร้างบัญชีผู้ดูแลคนแรก แล้วหมดอายุถาวร |

**การเพิ่มบัญชีผู้ใช้ระบบหลังจากนั้น** ไม่มีลิงก์สาธารณะ ต้องทำจากในระบบเท่านั้น
เข้าสู่ระบบด้วยบัญชีผู้ดูแล → แท็บ **ตั้งค่า** → หัวข้อ **บัญชีเจ้าหน้าที่** → ปุ่ม **เพิ่มบัญชี**
(เฉพาะสิทธิ์ผู้ดูแลระบบเท่านั้น เจ้าหน้าที่ทั่วไปเปิดหน้านี้ไม่ได้)

**ผู้ขอรับบริการไม่ต้องมีบัญชี** และไม่ต้องล็อกอิน Google ใด ๆ ทั้งสิ้น
ระบบยืนยันตัวตนจากเลขที่คำขอคู่กับอีเมลที่ใช้ยื่น หรือจาก token ในลิงก์ที่ส่งไปทางอีเมล

> ลิงก์ทั้งหมดนี้ดูและคัดลอกได้จากในระบบ ที่ **ตั้งค่า → ลิงก์ของระบบ**

**ข้อควรระวังเรื่อง `/dev` กับ `/exec`**
URL ที่ลงท้ายด้วย `/dev` คือเวอร์ชันทดสอบ เปิดได้เฉพาะเจ้าของสคริปต์และแสดงโค้ดล่าสุดเสมอ
**ห้ามแจกลิงก์ `/dev` ให้ผู้ขอรับบริการ** เพราะคนอื่นเปิดไม่ได้ ต้องแจก `/exec` เท่านั้น

## ขั้นตอนที่ 6 — เปิดใช้ AI สรุป Design Brief (ทางเลือก)

ถ้าข้ามขั้นตอนนี้ ระบบยังทำงานได้ครบทุกอย่าง เพียงแต่ Design Brief จะสรุปด้วยสูตรสำเร็จแทน AI

1. สมัครและสร้าง API key ที่ <https://console.anthropic.com>
2. ในเว็บแอป เข้าสู่ระบบเจ้าหน้าที่ → แท็บ **ตั้งค่า** → หัวข้อ **การเชื่อมต่อ AI สรุป Design Brief**
3. วาง API key แล้วกด **บันทึก**

**ค่าใช้จ่ายโดยประมาณ** คำขอหนึ่งใบใช้ราว 1,000–1,500 token ขาเข้า และ 400–600 token ขาออก

## การอัปเดตระบบเป็นเวอร์ชันใหม่

หลังติดตั้งครั้งแรกแล้ว การอัปเดตทำได้ด้วยคำสั่งเดียว **ไม่ต้องเข้าเบราว์เซอร์อีกเลย**

```bash
./deploy.sh                    # macOS และ Linux
.\deploy.ps1                   # Windows
```

หรือระบุคำอธิบายเวอร์ชันเอง

```bash
./deploy.sh "เพิ่มการแจ้งเตือนผู้ออกแบบ"
```

สคริปต์จะทำให้ตามลำดับ
1. **รันชุดทดสอบก่อน** ถ้าไม่ผ่านจะหยุดทันที ไม่อัปโหลดโค้ดเสีย
2. อัปโหลดโค้ดล่าสุดขึ้นโปรเจกต์ (`clasp push -f`)
3. ออกเวอร์ชันใหม่ทับ deployment เดิม (`clasp deploy -i`) — **URL ของเว็บแอปไม่เปลี่ยน**
   ผู้ใช้เห็นเวอร์ชันใหม่ทันทีเมื่อรีเฟรชหน้า

> ครั้งแรกสุดต้องกด **Deploy → New deployment** ในเบราว์เซอร์หนึ่งครั้งก่อน (ตามขั้นตอนที่ 4)
> หลังจากนั้น `./deploy.sh` จัดการให้ทั้งหมด

**ถ้าใช้วิธีคัดลอกไฟล์ด้วยมือ** ให้คัดลอกไฟล์จาก `dist/` ทับของเดิม แล้วกด
**Deploy → Manage deployments → ไอคอนดินสอ → Version: New version → Deploy**
(อย่ากด *New deployment* เพราะจะได้ URL ใหม่ ทำให้ลิงก์ที่แจกไปแล้วใช้ไม่ได้
และ Cloudflare ล็อกการจับคู่ไว้กับ deployment เดิม)

**อัปเดตฝั่ง Cloudflare** ทำหลังอัปเดต Apps Script เสมอ (ทั้งสองฝั่งต้องเป็นโค้ดรุ่นเดียวกัน)

```bash
npm run deploy:cf              # ทดสอบทั้งหมด แล้วอัปโหลดขึ้น Cloudflare
```

ระบบอยู่ในบัญชี Cloudflare ของคณะ (**pr@arts.tu.ac.th**) รหัสบัญชีล็อกไว้ใน `cloudflare/wrangler.jsonc` แล้ว
ต้องตั้ง `CLOUDFLARE_API_TOKEN` (สิทธิ์ *Edit Cloudflare Workers* ที่ครอบคลุมบัญชีของคณะ) หรือรัน `npx wrangler login` ด้วยบัญชีที่เป็นสมาชิกของบัญชีคณะ ในโฟลเดอร์ `cloudflare/` ก่อนหนึ่งครั้ง
ข้อมูลบน Cloudflare ไม่หายเมื่ออัปโหลดโค้ดใหม่ ไม่ต้องจับคู่ใหม่

## ระบบหลักบน Cloudflare

ระบบหลักอยู่ที่ **<https://design.tu-arts.workers.dev>** ใช้โค้ดชุดเดียวกับ Apps Script ทุกบรรทัด
(`cloudflare/build.js` นำไฟล์ `.gs` และ `.html` ทั้งหมดไปรวมกับตัวจำลองบริการของ Google ใน `cloudflare/prelude.js`)
จึงทำงานเหมือนกันทุกอย่าง แต่เร็วกว่ามากเพราะไม่ต้องรอ Google เปิดสเปรดชีตทุกครั้ง

### จับคู่ครั้งแรก (ทำครั้งเดียว)

1. อัปเดต Apps Script ให้เป็นโค้ดรุ่นล่าสุด (มีไฟล์ `15_Bridge.gs` รวมอยู่ใน `dist/Code.gs`)
   แล้ว **Deploy → Manage deployments → ดินสอ → New version → Deploy**
2. เปิด <https://design.tu-arts.workers.dev/setup>
3. กรอก **ลิงก์เว็บแอป Apps Script** (ลงท้ายด้วย `/exec`) อีเมลและรหัสผ่าน **ผู้ดูแลระบบ** แล้วกด **เชื่อมและย้ายข้อมูล**
4. ระบบย้ายข้อมูลทั้งหมด (คำขอ ผู้ใช้ ผู้ออกแบบ ตั้งค่า ไฟล์ CI งานเก็บถาวร) มาที่ Cloudflare ใช้เวลาไม่เกิน 1–2 นาที
5. เสร็จแล้ว Apps Script เปลี่ยนเป็นระบบสำรองทันที คนที่เปิดลิงก์ Apps Script เดิมจะถูกพามาที่ Cloudflare เอง
6. แจกลิงก์ใหม่ `https://design.tu-arts.workers.dev` ให้ผู้ขอรับบริการ และแจ้งเจ้าหน้าที่ให้เข้าสู่ระบบใหม่หนึ่งครั้ง
   (รหัสผ่านเดิมใช้ได้ แต่เบราว์เซอร์จำการเข้าสู่ระบบแยกตามโดเมน)

> Cloudflare รับจับคู่เฉพาะเว็บแอป Apps Script ของคณะ (รหัส deployment ใน `cloudflare/wrangler.jsonc` ค่า `GAS_DEPLOYMENT_ID`)
> คนอื่นจึงเอา Apps Script ของตัวเองมาจับคู่แย่งไม่ได้ ถ้าสร้าง deployment ใหม่ใน Apps Script ต้องแก้ค่านี้แล้ว `npm run deploy:cf`

> และจะถูกเขียนทับเมื่อแถวนั้นเปลี่ยนอีกครั้ง ให้แก้ผ่านหน้าเว็บเสมอ

### ตรวจสุขภาพระบบ

หน้า `/setup` แสดงสถานะการเชื่อมต่อ จำนวนชุดข้อมูลที่รอส่งไปสำรอง เวลาที่ส่งสำเร็จล่าสุด และข้อผิดพลาดล่าสุด
ส่วน **เครื่องมือผู้ดูแลระบบ** (ใช้อีเมลและรหัสผ่านผู้ดูแลระบบ)

- **ตรวจเทียบข้อมูลสองฝั่ง** เทียบทุกชีตทุกแถว บอกแถวแรกที่ไม่ตรง แสดงอีเมลที่ส่งไม่สำเร็จล่าสุด และลิงก์ Google Sheets สำรอง
- **ส่งข้อมูลทั้งหมดไปสำรองใหม่** เขียนทับชีตสำรองด้วยข้อมูลของ Cloudflare ทั้งหมด ใช้เมื่อตรวจเทียบแล้วไม่ตรง
  (เช่น มีคนเผลอแก้ในชีต)

ถ้า Google ล่มชั่วคราว Cloudflare ยังรับคำขอได้ตามปกติ (ใช้โฟลเดอร์ที่เตรียมไว้) ข้อมูลจะรอในคิวแล้วส่งครบเองเมื่อ Google กลับมา
อีเมลที่ค้างจะถูกส่งตอนนั้นเช่นกัน

### สลับกลับไปใช้ Apps Script (กรณี Cloudflare มีปัญหา)

1. เปิด `ลิงก์เว็บแอป Apps Script/exec?page=failover`
2. กรอกอีเมลและรหัสผ่านผู้ดูแลระบบ แล้วกด **ยืนยันกลับมาใช้ Apps Script**
3. Apps Script เป็นระบบหลักทันที (ข้อมูลทุกอย่างที่ Cloudflare ส่งมาถึงแล้วอยู่ครบ) แจกลิงก์ Apps Script ชั่วคราว
4. Apps Script แจ้ง Cloudflare ให้หยุดรับข้อมูลทันที ถ้า Cloudflare ล่มอยู่ Cloudflare จะรู้เองภายใน 5 นาทีหลังกลับมา
   ระหว่างนั้นลิงก์ Cloudflare จะแสดงหน้า "ระบบกลับไปใช้ Apps Script ชั่วคราว" พร้อมลิงก์ไปที่ Apps Script

**กลับมาใช้ Cloudflare** เปิด `/setup` แล้วจับคู่ใหม่ตามขั้นตอนเดิม ระบบดึงข้อมูลล่าสุดจาก Apps Script
(รวมคำขอที่ยื่นระหว่างสลับ) มาทับข้อมูลบน Cloudflare ถ้ามีการเปลี่ยนแปลงบน Cloudflare ที่ส่งไม่ถึง Apps Script
หน้า `/setup` จะบอกเลขงานที่ได้รับผลกระทบและขอให้ยืนยันก่อน

### ผู้ดูแลระบบลืมรหัสผ่าน

- มีผู้ดูแลระบบคนอื่น: ให้อีกคนตั้งรหัสใหม่ที่ **ตั้งค่า → บัญชีเจ้าหน้าที่** บนลิงก์ Cloudflare
- เป็นผู้ดูแลระบบคนเดียว: ใน Apps Script เพิ่มฟังก์ชันชั่วคราว
  `function tmpAdmin() { createAdmin_('pr@arts.tu.ac.th', 'ชื่อผู้ดูแลระบบ', 'รหัสผ่านใหม่'); }` กด **Run** แล้วลบทิ้ง
  จากนั้นสลับกลับไปใช้ Apps Script ด้วยรหัสใหม่ (หัวข้อด้านบน) แล้วจับคู่ใหม่ที่ `/setup`
  รหัสผ่านใหม่จะมาพร้อมข้อมูลที่ย้ายมา

| จับคู่ไม่ได้ ขึ้น *ลิงก์นี้ไม่ใช่เว็บแอป Apps Script ของระบบนี้* | ใช้ลิงก์ `/exec` จาก Deploy → Manage deployments ของ deployment เดิม |

| อีเมลส่งไม่สำเร็จ | ดูรายละเอียดด้วย **ตรวจเทียบข้อมูลสองฝั่ง** ส่วนใหญ่เป็นโควตา Gmail ต่อวัน |

## การใช้งานประจำวัน

### ผู้ขอรับบริการ

1. เปิด Web app URL → **ยื่นคำขอออกแบบ** ใต้แบบฟอร์มมี *คิวงานออกแบบตอนนี้* ให้ดูว่าแต่ละคนมีงานมากน้อยแค่ไหน
2. กรอก 3 ขั้นตอน: ข้อมูลผู้ขอ → รายละเอียดงาน (เลือกผู้ออกแบบที่ต้องการได้ที่ขั้นนี้) → แนบไฟล์และยืนยัน
3. รับอีเมลยืนยันพร้อมเลขที่คำขอและลิงก์ติดตาม
4. เมื่อได้รับแจ้งว่า *รอตรวจร่าง* ให้เปิดลิงก์ร่าง แล้วกด **อนุมัติ** หรือ **แจ้งจุดที่ต้องแก้ไข**
5. เมื่อสถานะเป็น *ส่งมอบแล้ว* ดาวน์โหลดไฟล์จากลิงก์ในอีเมลหรือหน้าติดตาม

### เจ้าหน้าที่

1. เปิด Web app URL → **สำหรับเจ้าหน้าที่** → เข้าสู่ระบบ
   (กดลิงก์ **เปิดคำขอนี้** ในอีเมลแจ้งเตือน ระบบจะเปิดงานใบนั้นให้ทันที)
2. แท็บ **คิวงาน** เริ่มที่ปุ่ม *งานที่ยังไม่เสร็จ* เรียงตามกำหนดใช้งานใกล้สุด
   - ปุ่มด้านบนตารางกรองตามสถานะ พร้อมจำนวนงาน ปุ่ม *เกินกำหนด* เป็นสีแดงเมื่อมีงานค้าง
   - ช่องค้นหากรองทันทีขณะพิมพ์ กด **รีเฟรช** เมื่อต้องการดึงคำขอใหม่ล่าสุด
   - **CSV** ส่งออกเฉพาะรายการที่แสดงอยู่ เปิดด้วย Excel ได้ทันที (ภาษาไทยไม่เพี้ยน)
3. คลิกแถวเพื่อเปิดรายละเอียด จะเห็น
   - **Design Brief** ที่ AI สรุปให้ พร้อมรายการ *ข้อมูลที่ยังขาด* สำหรับสอบถามในคราวเดียว
   - ข้อมูลดิบจากแบบฟอร์ม ไฟล์แนบ ประวัติการแก้ไข และไทม์ไลน์
4. กล่อง **เปลี่ยนสถานะ** แสดงครบทุกสถานะ
   - ปุ่ม**ขอบทึบ** คือขั้นถัดไปตามปกติ
   - ปุ่ม**ขอบประ** คือข้ามขั้นหรือย้อนขั้น กดได้เหมือนกัน ใช้ตอนที่คุยกับผู้ขอโดยตรงแล้วแก้เสร็จทันที
   - เปิดงานที่ส่งมอบหรือยกเลิกแล้วกลับมาทำต่อได้ ระบบล้างวันที่ส่งมอบเดิมให้ แดชบอร์ดจึงนับถูก
   - ทุกครั้งที่เปลี่ยนสถานะ เลือกได้ว่าจะส่งอีเมลแจ้งผู้ขอหรือไม่ (ค่าเริ่มต้นคือส่ง)
   - ยังมีเงื่อนไขที่บังคับอยู่ 3 ข้อ: *รอตรวจร่าง* ต้องมีลิงก์ร่าง, *ยกเลิกคำขอ* ต้องมีเหตุผล,
     *รอข้อมูลเพิ่มเติม* ต้องระบุรายการที่ขาด
5. แท็บ **แดชบอร์ด** ใช้ประกอบรายงานประจำปี แท็บ **คลังผลงาน** ใช้ค้นงานเก่า

## ฟีเจอร์ช่วยทำงาน

### แก้ไขข้อมูลคำขอ (เจ้าหน้าที่)
เปิดงาน → **แก้ไขข้อมูล** แก้ได้ทุกช่อง ทั้งกำหนดใช้งาน ข้อมูลผู้ประสานงาน รายละเอียด และรายการชิ้นงาน
ระบบบันทึกในประวัติว่าใครแก้อะไร (ไม่แสดงให้ผู้ขอเห็น) เลือกส่งอีเมลแจ้งผู้ขอได้
ถ้าแก้ข้อมูลที่ใช้สรุปโจทย์ ระบบสรุป Design Brief ใหม่ให้อัตโนมัติภายในไม่กี่นาที

### ผู้ขอตอบ "รอข้อมูลเพิ่มเติม" ผ่านระบบ
เมื่อเปลี่ยนสถานะเป็น *รอข้อมูลเพิ่มเติม* อีเมลถึงผู้ขอมีปุ่ม **ตอบและแนบไฟล์**
ผู้ขอพิมพ์คำตอบและแนบไฟล์ได้ (สูงสุดตามค่า "จำนวนไฟล์แนบสูงสุด" ต่อการตอบหนึ่งครั้ง)
เมื่อส่งแล้วงานกลับไปสถานะเดิมก่อนขอข้อมูลเองทันที และเจ้าหน้าที่ได้รับอีเมลพร้อมคำตอบ
คำตอบทั้งหมดอยู่ในการ์ด *ข้อมูลที่ผู้ขอส่งเพิ่ม* ของหน้ารายละเอียดงาน

### กำหนดส่งร่างแรก
นับตามค่า "ส่งร่างแรกภายใน (วันทำการ)" ในหน้าตั้งค่า เริ่มนับจากวันยื่นคำขอ
หรือวันที่ผู้ขอส่งข้อมูลเพิ่มเติมครั้งล่าสุด (ไม่นับเสาร์ อาทิตย์ แต่ยังไม่รู้จักวันหยุดนักขัตฤกษ์)
คิวงานแสดงกำหนดใต้วันที่ใช้งาน มีปุ่ม *ร่างแรกเกินกำหนด* และอีเมลสรุปเช้า 08:00 น. แจ้งงานที่เกินหรือใกล้ครบ

### ประเมินความพึงพอใจ
เมื่อส่งมอบงาน อีเมลชวนผู้ขอประเมิน 1–5 ดาวพร้อมความเห็น ผ่านหน้าติดตามงาน
คะแนน 1–2 ดาวแจ้งเจ้าหน้าที่ทางอีเมลทันที แดชบอร์ดแสดงคะแนนเฉลี่ย สัดส่วนการตอบ และความเห็นล่าสุด
ไฟล์ CSV ที่ส่งออกมีคอลัมน์คะแนนและความเห็นด้วย

### ผู้ออกแบบและคิวงานบนหน้ายื่นคำขอ
**ตั้งค่าครั้งแรก (ผู้ดูแลระบบ):** ตั้งค่า → การ์ด **ผู้ออกแบบ** → *เพิ่มผู้ออกแบบ* ทีละคน (ทีมมี 4 คน ระบบให้ 4 สีไม่ซ้ำกันอัตโนมัติ)
- **ชื่อ-นามสกุล** ที่ผู้ขอเห็น · **ชื่อย่อบนปฏิทิน** (เว้นว่างได้ ใช้ชื่อแรก) · **ความถนัด** เช่น โปสเตอร์ วิดีโอสั้น
- **อีเมล** (ไม่บังคับ) ใส่แล้วผู้ออกแบบได้รับแจ้งเมื่อผู้ขอเลือกตัวเอง หรือเมื่อถูกมอบหมายงาน
- **รับงานพร้อมกันได้** ใช้คำนวณแถบความหนัก (ค่าเริ่มต้น 6 งาน) ระดับคือ ว่าง → งานน้อย → ปานกลาง → ค่อนข้างมาก → เต็ม
- **รับงานใหม่** ปิดชั่วคราวเมื่อลาหรืองานเต็ม ผู้ขอจะเลือกคนนั้นไม่ได้แต่ยังเห็นงานในมือ
- **แสดงให้ผู้ขอเห็น** ปิดเมื่อไม่ได้ปฏิบัติงานแล้ว (ลบได้เฉพาะคนที่ไม่มีงานค้าง)

ถ้าเคยพิมพ์ชื่อผู้รับผิดชอบไว้ในงานเดิม การ์ดจะแนะนำชื่อเหล่านั้นให้กดเพิ่ม งานเดิมจะนับเป็นของคนนั้นทันที
เปลี่ยนชื่อผู้ออกแบบภายหลังได้ ระบบเปลี่ยนชื่อในงานที่ผูกอยู่ให้ด้วย

**ผู้ขอ:** ขั้นที่ 2 ของแบบฟอร์ม **ต้องเลือก** ผู้ออกแบบที่ต้องการ หรือกดเลือก *ให้ฝ่ายฯ จัดสรรให้* ถ้ายังไม่แน่ใจ
(ไม่เลือกจะไปขั้นถัดไปไม่ได้ ระบบที่ยังไม่มีรายชื่อผู้ออกแบบจะซ่อนช่องนี้และไม่บังคับ)
ใต้แบบฟอร์มมีคิวงาน 3 ส่วนที่เชื่อมกัน: แถบภาระงานของแต่ละคน ปฏิทินรายเดือน (จุดสีตามผู้ออกแบบพร้อมชื่องานย่อ)
และตารางงานที่กำลังทำ (ชื่อโครงการ กำหนดใช้งาน สถานะ ผู้ออกแบบ) กดชื่อใครก็ได้หรือเลือกผู้ออกแบบในแบบฟอร์ม
ทั้งปฏิทินและตารางจะแสดงเฉพาะงานของคนนั้น หน้าติดตามงานของผู้ขอแสดงผู้ออกแบบของงานด้วย

**เจ้าหน้าที่:** คิวงานมีคอลัมน์ **ผู้รับผิดชอบ** เป็น dropdown เจ้าหน้าที่ทุกคน (ไม่ต้องเป็นผู้ดูแลระบบ)
เปลี่ยนผู้รับผิดชอบได้ทันทีโดยไม่ต้องเปิดงาน ตัวเลือกแบ่งเป็น *ผู้ออกแบบ* และ *บัญชีเจ้าหน้าที่อื่น*
(บัญชีที่เปิดใช้งานอยู่ในหัวข้อบัญชีเจ้าหน้าที่) พร้อมจำนวนงานในมือของแต่ละคน งานที่ยังไม่มอบหมายเป็นสีเหลือง
ผู้ได้รับมอบหมายได้อีเมลแจ้ง (อีเมลในรายชื่อผู้ออกแบบ หรืออีเมลบัญชีเจ้าหน้าที่ที่ชื่อตรงกัน)
ตัวกรอง *ผู้รับผิดชอบ* ด้านบนใช้ดูงานของแต่ละคนหรืองานที่ยังไม่มอบหมาย
ปุ่ม **มอบหมาย** ในหน้ารายละเอียดงานทำได้เหมือนกัน และมีตัวเลือก *ชื่ออื่นที่ไม่อยู่ในรายชื่อ* สำหรับคนนอกทีม
งานที่มอบให้บัญชีเจ้าหน้าที่หรือชื่ออื่น ผู้ขอจะเห็นเป็น "เจ้าหน้าที่ฝ่ายฯ" ไม่เห็นชื่อจริง
ถ้าต้องการให้ผู้ขอเห็นชื่อและเลือกคนนั้นได้ ให้เพิ่มเป็นผู้ออกแบบในหน้าตั้งค่า

คิวงานบนหน้ายื่นคำขอเปิดให้ทุกคนเห็นโดยไม่ต้องเข้าสู่ระบบ จึงแสดงเฉพาะชื่อโครงการ กำหนดใช้งาน สถานะ และผู้ออกแบบ
ไม่มีข้อมูลผู้ขอ ถ้าไม่ต้องการแสดง ปิดได้ที่ ตั้งค่า → **แสดงคิวงานบนหน้ายื่นคำขอ**

### ปฏิทินงาน
แท็บ **ปฏิทิน** แสดงกำหนดใช้งาน วันจัดงาน และกำหนดส่งร่างแรกของทุกงานในรูปปฏิทินรายเดือน
สีตามสถานะ (ติ๊ก *สีตามผู้ออกแบบ* เพื่อเปลี่ยนเป็นสีของแต่ละคน) กดที่งานเพื่อเปิดรายละเอียด
ด้านขวาแสดงภาระงานของแต่ละคนรวมคนที่ยังว่าง บนมือถือจะแสดงเป็นรายการตามวันแทน

### คลังไฟล์ CI
แท็บ **ไฟล์ CI** เพิ่มได้ทั้งไฟล์ (ไม่เกิน 25 MB) และลิงก์ (เช่น เทมเพลต Canva หรือโฟลเดอร์ Drive ที่มีไฟล์ใหญ่)
ไฟล์เก็บในโฟลเดอร์ `คลังไฟล์ CI (ดาวน์โหลดได้)` บน Drive และเปิดสิทธิ์ให้ทุกคนที่มีลิงก์ดาวน์โหลดได้
ผู้ขอเปิดได้จากหน้าแรก (แถบ *คลังไฟล์ CI*) หรือลิงก์ `?page=resources` ที่คัดลอกได้จากแท็บนี้
ถ้ามหาวิทยาลัยไม่อนุญาตให้แชร์ไฟล์แบบสาธารณะ จะดาวน์โหลดได้เฉพาะบัญชี @tu.ac.th

### ย้ายข้อมูลเก่าไปเก็บถาวร
ตั้งค่า → **ย้ายข้อมูลเก่าไปเก็บถาวร** เลือกช่วง กด *ตรวจสอบก่อนย้าย* แล้วพิมพ์ `ย้ายข้อมูล`
ย้ายเฉพาะงานที่ส่งมอบหรือยกเลิกแล้ว ไปเก็บในสเปรดชีตแยกในโฟลเดอร์ระบบ
งานที่ย้ายแล้วยังเปิดจากลิงก์อีเมลได้ (อ่านอย่างเดียว) แดชบอร์ดและคลังผลงานยังนับรวม
แนะนำให้ทำปีละครั้งหลังเริ่มปีงบประมาณใหม่ ในช่วงที่ไม่มีคนใช้งาน

## การลบคำขอและการล้างข้อมูลทดลอง

ก่อนเปิดใช้จริงมักมีคำขอที่กรอกไว้ทดลอง ระบบมีวิธีลบให้สองแบบ ทั้งสองแบบ**ทำได้เฉพาะบัญชีผู้ดูแลระบบ**

### ลบทีละใบ

1. เข้าสู่ระบบ → แท็บ **คิวงาน** → คลิกคำขอที่ต้องการลบ
2. กดปุ่มแดง **ลบคำขอถาวร** ท้ายหน้าต่างรายละเอียด
3. ระบบจะให้พิมพ์เลขที่คำขอ เช่น `DR-2569-0001` ให้ตรงเพื่อยืนยัน

การลบหนึ่งใบจะลบ **ทุกอย่างที่ผูกกับคำขอนั้น** คือ แถวในชีต Requests, Deliverables,
Attachments, Revisions และ Timeline พร้อมย้ายไฟล์และโฟลเดอร์ของงานบน Google Drive ลงถังขยะ
(กู้คืนจากถังขยะได้ภายใน 30 วัน) ระบบจะบันทึกไว้ในไทม์ไลน์ใต้ชื่อ `SYSTEM` ว่าใครลบงานใดเมื่อไหร่

### ล้างข้อมูลทดลองทั้งหมดทีเดียว

1. เข้าสู่ระบบ → แท็บ **ตั้งค่า** → เลื่อนลงล่างสุดถึงการ์ดแดง **โซนอันตราย**
2. กด **ล้างข้อมูลคำขอทั้งหมด** แล้วพิมพ์ข้อความ `ล้างข้อมูลทั้งหมด` ให้ตรงทุกตัวอักษร

คำสั่งนี้ล้างคำขอทุกใบ ไฟล์ ประวัติ และ**รีเซ็ตตัวนับเลขที่คำขอกลับไปเริ่มที่ 0001**
เหมาะกับการใช้ครั้งเดียวตอนจบการทดลองก่อนเปิดใช้จริง
บัญชีผู้ใช้และค่าตั้งค่าทั้งหมดจะไม่ถูกแตะ จึงไม่ต้องติดตั้งระบบใหม่

> ทั้งสองคำสั่งนี้ย้อนกลับไม่ได้ ถ้าไม่แน่ใจ ให้เปิดสเปรดชีตแล้วสั่ง
> **File → Make a copy** เก็บไว้ก่อน

### ถ้าลบแถวในสเปรดชีตเองได้ไหม

ได้ และคำขอจะหายจากหน้าเว็บทันที เพราะระบบอ่านตรงจากชีต **แต่ไม่แนะนำ** เพราะ

- แถวในชีต Deliverables, Attachments, Revisions และ Timeline ของงานนั้นจะค้างเป็นข้อมูลกำพร้า
- โฟลเดอร์และไฟล์บน Google Drive ยังอยู่ กินพื้นที่ไปเรื่อย ๆ
- ตัวนับเลขที่คำขอไม่ถอยกลับ เลขถัดไปจะข้ามไปเลย
- ถ้าเผลอลบแถวหัวตาราง (แถวที่ 1) ระบบจะอ่านชีตไม่ออกทั้งชีต

ถ้าจำเป็นต้องแก้ในชีตจริง ๆ ให้แก้เฉพาะค่าในเซลล์ อย่าลบหรือสลับคอลัมน์

## เปิดลิงก์เว็บแอปไม่ได้ ทำอย่างไร

อาการ: คัดลอก URL จาก Deploy มาเปิดแล้วขึ้นหน้าขออนุญาต เข้าไม่ได้ หรือขึ้นหน้าเปล่า
ไล่ตรวจตามลำดับนี้ ส่วนใหญ่จบที่ข้อ 1 หรือ 2

**1. คัดลอกผิดช่อง** — ในกล่อง *Manage deployments* มี URL อยู่ 2 ช่อง

| ช่อง | หน้าตา | ใช้ได้ไหม |
|---|---|---|
| **Web app → URL** | `.../macros/s/AKfycb.../exec` | ✅ ช่องนี้เท่านั้น |
| Library → URL | `.../macros/library/d/.../2` | ❌ เปิดเป็นหน้าเว็บไม่ได้ |

URL ในกล่องจะถูกตัดด้วย `…` ให้กดปุ่ม **Copy** ใต้หัวข้อ *Web app* อย่าลากเมาส์คลุมเอง

**2. ล็อกอิน Google หลายบัญชีพร้อมกัน** — สาเหตุที่พบบ่อยที่สุด
สังเกตแถบที่อยู่ ถ้าขึ้น `script.google.com/u/1/...` แปลว่ากำลังใช้บัญชีลำดับที่ 2
เวลาเปิดลิงก์ `/exec` เบราว์เซอร์จะเปิดด้วยบัญชีหลัก (`u/0`) ซึ่งอาจไม่มีสิทธิ์

*วิธีทดสอบให้รู้ผลทันที* เปิดลิงก์ `/exec` ใน **หน้าต่างไม่ระบุตัวตน (Incognito)**
- เปิดได้ → เป็นปัญหาหลายบัญชีในเบราว์เซอร์เท่านั้น ระบบไม่มีปัญหา
  แก้โดยออกจากบัญชีอื่นให้เหลือบัญชีเดียว หรือใช้โปรไฟล์เบราว์เซอร์แยก
- เปิดไม่ได้เหมือนกัน → ไปข้อ 3

**3. ตั้งค่าสิทธิ์ของ deployment ผิด**
Deploy → **Manage deployments** → ไอคอนดินสอ → ตรวจว่า

| ช่อง | ต้องเป็น |
|---|---|
| Execute as | **Me** |
| Who has access | **Anyone** |

ถ้าเป็น *Only myself* หรือ *Anyone with Google Account* คนนอกจะเปิดไม่ได้
แก้แล้วต้องกด **Deploy** ซ้ำเพื่อให้มีผล

**4. ใช้ URL ที่ลงท้าย `/dev`** — เปิดได้เฉพาะเจ้าของสคริปต์ ห้ามแจกให้ผู้อื่น

**5. หา URL ที่ถูกต้องไม่เจอเลย** — ในตัวแก้ไข Apps Script เลือกฟังก์ชัน **`showLinks`**
แล้วกด **Run** จากนั้นเปิด **Execution log** ระบบจะพิมพ์ลิงก์ที่ถูกต้องทั้งหมดให้
พร้อมบอกว่ามีบัญชีเจ้าหน้าที่กี่บัญชี มีคำขอกี่รายการ และอีเมลใดได้รับแจ้งเตือนบ้าง

## เปิด Apps Script จากในชีตแล้วเจอโค้ดว่างเปล่า

**เป็นเรื่องปกติ ไม่ใช่ความผิดพลาด** และ **ห้ามวางโค้ดลงในโปรเจกต์นั้น**

สเปรดชีตฐานข้อมูลถูกสร้างขึ้นโดยสคริปต์ จึงไม่ใช่ชีตที่ผูกกับสคริปต์ (ไม่ใช่ container-bound)
เมื่อกด **Extensions → Apps Script** จากในชีต Google จะ **สร้างโปรเจกต์ใหม่ที่ว่างเปล่า**
ชื่อ *Untitled project* ให้เสมอ ซึ่งไม่เกี่ยวข้องกับระบบเลย

โปรเจกต์จริงของระบบชื่อ **ระบบขอรับบริการออกแบบสื่อ - ฝ่ายสื่อสารองค์กร**
เปิดได้จาก <https://script.google.com/home> หรือจากลิงก์ที่ `showLinks` พิมพ์ให้
โปรเจกต์ *Untitled project* ที่เผลอสร้างไว้ ลบทิ้งได้เลยโดยไม่กระทบอะไร

## การทดสอบโค้ดก่อนแก้ไข

โครงการมีชุดทดสอบอัตโนมัติที่รันได้บนเครื่องโดยไม่ต้องแตะระบบจริง

```bash
npm test          # ทั้งหมด: Apps Script 289 รายการ + Cloudflare 40 รายการ
npm run test:gas  # เฉพาะ Apps Script
npm run test:cf   # เฉพาะ Cloudflare (ต้องใช้ Node 22.5 ขึ้นไป รุ่นเก่ากว่าจะข้ามให้เอง)
```

ชุดทดสอบ Cloudflare รัน Durable Object ตัวจริงบน SQLite ของ Node คู่กับ Apps Script ตัวจำลองผ่าน `doPost` จริง
ครอบคลุมการจับคู่ การย้ายข้อมูล การยื่นคำขอพร้อมไฟล์ งานของเจ้าหน้าที่ การส่งสำรองครบทุกแถว
Google ล่มแล้วกลับมา การสลับกลับไปใช้ Apps Script และการจับคู่ใหม่

ชุดทดสอบจำลอง Google Apps Script ทั้งหมด (Sheets, Drive, Gmail, Properties, Cache, Lock,
Triggers และ Claude API) จึงตรวจได้ทั้งการตรวจสอบข้อมูล การเปลี่ยนสถานะ สิทธิ์การเข้าถึง
รอบการแก้ไข การส่งอีเมล และการเรียก Claude API **ควรรันให้ผ่านทุกครั้งก่อนนำโค้ดขึ้นระบบจริง**
