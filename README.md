# ระบบขอรับบริการออกแบบสื่อประชาสัมพันธ์

ฝ่ายสื่อสารองค์กร คณะศิลปศาสตร์ มหาวิทยาลัยธรรมศาสตร์

ระบบรับคำขอออกแบบสื่อประชาสัมพันธ์แบบช่องทางเดียว (Single Entry Point) พร้อมออกเลขที่งาน
ทะเบียนคิวกลาง ระบบติดตามสถานะที่ผู้ขอตรวจสอบได้เอง และแดชบอร์ดสรุปผลการให้บริการ
พัฒนาด้วย **Google Apps Script** โดยใช้ **Google Sheets เป็นฐานข้อมูล** และ **Google Drive เก็บไฟล์งาน**
ทำงานทั้งหมดภายใต้บัญชี `pr@arts.tu.ac.th` ไม่ต้องเช่าเซิร์ฟเวอร์

> ออกแบบตาม Workshop Canvas "ออกแบบ Workflow ใหม่จากงานจริง"
> เพื่อแก้ปัญหาหลัก 2 ข้อ คือ **ข้อมูลคำขอไม่ครบตั้งแต่ต้นทาง** และ **ไม่มีระบบติดตามสถานะที่ตรวจสอบได้**

---

## ระบบทำอะไรได้

| ขั้นตอนใน Workflow ใหม่ | สิ่งที่ระบบทำให้ |
|---|---|
| 1. รับคำขอผ่านแบบฟอร์มเดียว | แบบฟอร์ม 3 ขั้นตอน บังคับกรอกข้อมูลจำเป็นและแนบไฟล์ ตรวจสอบทั้งฝั่งเบราว์เซอร์และเซิร์ฟเวอร์ |
| 2. ระบบตอบกลับอัตโนมัติ | ออกเลขที่คำขอ `DR-2569-0001` และส่งอีเมลยืนยันพร้อมลิงก์ติดตามทันที |
| 3. AI สรุป Design Brief | ส่งคำตอบทั้งหมดให้ Claude สรุปเป็นโจทย์งานมาตรฐาน พร้อมระบุ **ข้อมูลที่ยังขาด** เพื่อสอบถามในคราวเดียว |
| 4. บันทึกลงทะเบียนคิวกลาง | ทุกคำขอลง Google Sheets พร้อมจัดระดับความเร่งด่วนอัตโนมัติจากกำหนดส่ง |
| 5. ออกแบบร่างชิ้นงาน | มอบหมายผู้รับผิดชอบ บันทึกลิงก์ร่าง และบันทึกภายในของทีม |
| 6. ตรวจร่างและแก้ไขออนไลน์ | ผู้ขอแจ้งจุดแก้ไขผ่านระบบ นับรอบอัตโนมัติและบังคับเพดาน 3 รอบ |
| 7. ส่งมอบไฟล์ฉบับสมบูรณ์ | โฟลเดอร์ Drive แยกตามเลขที่งาน ตั้งชื่อไฟล์มาตรฐาน `DR-2569-0001_FINAL_ชื่อโครงการ_01.pdf` |
| 8. อัปเดตสถานะอัตโนมัติ | อีเมลแจ้งทุกครั้งที่สถานะเปลี่ยน และหน้าติดตามที่เปิดดูได้ตลอดเวลา |
| 9. สรุปผลการให้บริการ | แดชบอร์ดจำนวนงาน ประเภทสื่อ ระยะเวลาเฉลี่ย รอบแก้ไขเฉลี่ย และร้อยละคำขอที่ข้อมูลครบตั้งแต่ครั้งแรก |

### สถานะงาน 5 ระดับ (พร้อมสถานะยกเว้น 2 สถานะ)

```
รับคำขอ ──▶ อยู่ระหว่างออกแบบ ──▶ รอตรวจร่าง ──▶ ส่งมอบแล้ว
                                     │  ▲
                                     ▼  │
                               อยู่ระหว่างแก้ไข

สถานะยกเว้น: รอข้อมูลเพิ่มเติม / ยกเลิกคำขอ
```

## เริ่มต้นใช้งาน

อ่านคู่มือฉบับเต็มที่ **[docs/DEPLOY.md](docs/DEPLOY.md)** สรุปสั้น ๆ คือ

ต้องเปิด Apps Script API ที่ <https://script.google.com/home/usersettings> ด้วยบัญชี pr@arts.tu.ac.th ก่อนหนึ่งครั้ง จากนั้น

```bash
./setup.sh          # macOS และ Linux
.\setup.ps1         # Windows (PowerShell)
```

สคริปต์จะเข้าสู่ระบบ Google สร้างโปรเจกต์ Apps Script และอัปโหลดโค้ดให้ทั้งหมด
เหลือทำเองเพียง 2 อย่างที่ Google บังคับให้มีคนกดจริง

1. **Deploy** เป็น Web app แบบ *Execute as: Me* และ *Who has access: Anyone*
2. **เปิด Web app URL** — ระบบจะติดตั้งฐานข้อมูล โฟลเดอร์ และทริกเกอร์ให้เอง
   แล้วส่งรหัสติดตั้งไปที่อีเมล pr@arts.tu.ac.th เพื่อสร้างบัญชีผู้ดูแลระบบผ่านหน้าเว็บ

ตั้งค่า Claude API key ได้ที่หน้าเจ้าหน้าที่ → ตั้งค่า (ทางเลือก)

## ฐานข้อมูล (Google Sheets 8 ชีต)

| ชีต | เก็บอะไร |
|---|---|
| `Requests` | คำขอหนึ่งใบต่อหนึ่งแถว รวมสถานะ Design Brief และเวลาแต่ละขั้น |
| `Deliverables` | รายการชิ้นงานที่ขอ แยกตามประเภทสื่อและขนาด |
| `Attachments` | ทะเบียนไฟล์ทั้งไฟล์ต้นทางและไฟล์ส่งมอบ |
| `Revisions` | ข้อแก้ไขแต่ละรอบจากผู้ขอรับบริการ |
| `Timeline` | ประวัติทุกการเปลี่ยนแปลง ใช้ตรวจสอบย้อนหลังได้ |
| `Users` | บัญชีเจ้าหน้าที่ (รหัสผ่านเก็บเป็นค่าแฮชพร้อม salt) |
| `Settings` | ค่าตั้งค่าที่แก้ได้จากหน้าเว็บ |
| `Counters` | ตัวนับเลขที่คำขอ แยกตามปี พ.ศ. |

## ความปลอดภัย

- รหัสผ่านเจ้าหน้าที่เก็บเป็นค่าแฮช HMAC-SHA256 วนซ้ำ 2,000 รอบ พร้อม salt รายบัญชีและกุญแจลับของระบบ
- Session ใช้ token ที่เซ็นด้วย HMAC มีอายุ 12 ชั่วโมง ปลอมแปลงไม่ได้ และตัดสิทธิ์ทันทีเมื่อปิดบัญชี
- ล็อกบัญชี 15 นาทีเมื่อกรอกรหัสผ่านผิดเกิน 5 ครั้ง
- ผู้ขอรับบริการเข้าถึงงานของตนเองได้ด้วยเลขที่คำขอคู่กับอีเมล หรือด้วย token ในลิงก์จากอีเมลเท่านั้น
- หน้าติดตามไม่เปิดเผยข้อมูลภายใน (Design Brief, บันทึกภายใน, ผู้รับผิดชอบ, ลิงก์โฟลเดอร์)
- ข้อความจากผู้ใช้ถูก escape ก่อนแสดงผลทุกจุดทั้งในเว็บและในอีเมล
- พารามิเตอร์ใน URL ถูกกรองด้วยรายการอักขระที่อนุญาต และ JSON ที่ฝังในหน้าเว็บหลบอักขระ `< > &`
- จำกัดการยื่นคำขอ 5 รายการต่อชั่วโมงต่อหนึ่งอีเมล
- ทุกการเขียนที่ต้องออกเลขหรือเปลี่ยนสถานะทำภายใต้ `LockService` เพื่อกันข้อมูลชนกัน
- API key ของ Claude เก็บใน Script Properties ไม่ปรากฏในโค้ดหรือหน้าเว็บ

## การทดสอบ

```bash
npm test        # หรือ  TZ=Asia/Bangkok node tests/run.js
```

ชุดทดสอบ 149 รายการครอบคลุม การติดตั้งระบบ การตรวจสอบข้อมูลแบบฟอร์ม การออกเลขที่งาน
การแนบไฟล์ การส่งอีเมล สิทธิ์การเข้าถึงหน้าติดตาม เส้นทางการเปลี่ยนสถานะ รอบการแก้ไข
การเรียก Claude API และการสำรองเมื่อ API ล้มเหลว งานเบื้องหลัง ระบบเข้าสู่ระบบ สถิติ
และการป้องกันการแทรกโค้ด — โดยจำลอง Google Apps Script ทั้งหมดจึงรันได้โดยไม่แตะระบบจริง
