# ระบบขอรับบริการออกแบบสื่อประชาสัมพันธ์

ฝ่ายสื่อสารองค์กร คณะศิลปศาสตร์ มหาวิทยาลัยธรรมศาสตร์

ระบบรับคำขอออกแบบสื่อประชาสัมพันธ์แบบช่องทางเดียว (Single Entry Point) พร้อมออกเลขที่งาน
ทะเบียนคิวกลาง ระบบติดตามสถานะที่ผู้ขอตรวจสอบได้เอง และแดชบอร์ดสรุปผลการให้บริการ
ระบบหลักทำงานบน **Cloudflare Workers** (เร็ว ตอบในระดับมิลลิวินาที) ที่ <https://larts-design.mcorner-ap.workers.dev>
โดยมี **Google Apps Script** เป็นระบบสำรองอัตโนมัติ ได้สำเนาข้อมูลทุกแถวใน **Google Sheets** ทันที
และเป็นคนเก็บไฟล์งานบน **Google Drive** กับส่งอีเมลจากบัญชี `pr@arts.tu.ac.th` ไม่ต้องเช่าเซิร์ฟเวอร์
โค้ดของระบบมีชุดเดียว (`apps-script/`) ใช้ได้ทั้งสองที่ ถ้า Cloudflare มีปัญหาสลับกลับไปใช้ Apps Script ได้ทันที

> ออกแบบตาม Workshop Canvas "ออกแบบ Workflow ใหม่จากงานจริง"
> เพื่อแก้ปัญหาหลัก 2 ข้อ คือ **ข้อมูลคำขอไม่ครบตั้งแต่ต้นทาง** และ **ไม่มีระบบติดตามสถานะที่ตรวจสอบได้**

## ระบบทำอะไรได้

| ขั้นตอนใน Workflow ใหม่ | สิ่งที่ระบบทำให้ |
|---|---|
| 1. รับคำขอผ่านแบบฟอร์มเดียว | แบบฟอร์ม 3 ขั้นตอน บังคับกรอกข้อมูลจำเป็นและแนบไฟล์ ตรวจสอบทั้งฝั่งเบราว์เซอร์และเซิร์ฟเวอร์ |
| 2. ระบบตอบกลับอัตโนมัติ | ออกเลขที่คำขอ `DR-2569-0001` และส่งอีเมลยืนยันพร้อมลิงก์ติดตามทันที |
| 3. AI สรุป Design Brief | ส่งคำตอบทั้งหมดให้ Claude สรุปเป็นโจทย์งานมาตรฐาน พร้อมระบุ **ข้อมูลที่ยังขาด** เพื่อสอบถามในคราวเดียว |
| 4. บันทึกลงทะเบียนคิวกลาง | ทุกคำขอลง Google Sheets พร้อมจัดระดับความเร่งด่วนอัตโนมัติจากกำหนดส่ง |
| 5. ออกแบบร่างชิ้นงาน | คิวงานมีคอลัมน์ผู้รับผิดชอบเป็น dropdown เจ้าหน้าที่ทุกคนเปลี่ยนผู้รับผิดชอบได้ทันที (ผู้ออกแบบหรือบัญชีเจ้าหน้าที่) พร้อมอีเมลแจ้ง บันทึกลิงก์ร่าง และบันทึกภายในของทีม |
| 6. ตรวจร่างและแก้ไขออนไลน์ | ผู้ขอแจ้งจุดแก้ไขผ่านระบบ นับรอบอัตโนมัติและบังคับเพดาน 3 รอบ |
| 7. ส่งมอบไฟล์ฉบับสมบูรณ์ | โฟลเดอร์ Drive แยกตามเลขที่งาน ตั้งชื่อไฟล์มาตรฐาน `DR-2569-0001_FINAL_ชื่อโครงการ_01.pdf` |
| 8. อัปเดตสถานะอัตโนมัติ | อีเมลแจ้งทุกครั้งที่สถานะเปลี่ยน และหน้าติดตามที่เปิดดูได้ตลอดเวลา |
| 9. สรุปผลการให้บริการ | แดชบอร์ดจำนวนงาน ประเภทสื่อ ระยะเวลาเฉลี่ย รอบแก้ไขเฉลี่ย และร้อยละคำขอที่ข้อมูลครบตั้งแต่ครั้งแรก เลือกดูรายปีงบประมาณได้ ส่งออก CSV สำหรับรายงานประจำปี |
| 10. ฟีเจอร์ช่วยทำงาน | เจ้าหน้าที่แก้ข้อมูลคำขอได้เอง · ผู้ขอตอบ "รอข้อมูลเพิ่มเติม" พร้อมแนบไฟล์ผ่านระบบ · เตือนกำหนดส่งร่างแรกตามเงื่อนไขบริการ · แบบประเมินความพึงพอใจหลังส่งมอบ · ปฏิทินงานและภาระงานแต่ละคน · คลังไฟล์ CI ให้ดาวน์โหลดเอง |
| 11. เลือกผู้ออกแบบและดูคิวงาน | ผู้ขอต้องเลือกผู้ออกแบบที่ต้องการเอง (หรือกดเลือก "ให้ฝ่ายฯ จัดสรรให้") ใต้แบบฟอร์มแสดงคิวงานปัจจุบัน: แถบความหนักและจำนวนงานของแต่ละคน ปฏิทินรายเดือนแยกสีตามผู้ออกแบบ และตารางงานที่กำลังทำ กดชื่อใครก็ได้เพื่อดูเฉพาะงานของคนนั้นทั้งปฏิทินและตาราง |
| 12. ดูแลข้อมูลหลังบ้าน | ลบคำขอทีละใบ ล้างข้อมูลทดลอง และย้ายงานเก่าที่ปิดแล้วไปเก็บถาวรเพื่อให้ระบบเร็วตลอด (งานที่ย้ายแล้วยังเปิดดูได้) |

### สถานะงาน 5 ระดับ (พร้อมสถานะยกเว้น 2 สถานะ)

```
รับคำขอ ──▶ อยู่ระหว่างออกแบบ ──▶ รอตรวจร่าง ──▶ ส่งมอบแล้ว
                                     │  ▲
                                     ▼  │
                               อยู่ระหว่างแก้ไข

สถานะยกเว้น: รอข้อมูลเพิ่มเติม / ยกเลิกคำขอ
```

เส้นทางข้างบนคือขั้นตอนปกติ เจ้าหน้าที่ข้ามขั้น ย้อนขั้น หรือเปิดงานที่ปิดแล้วอีกครั้งได้จากหน้าจัดการงาน
สำหรับกรณีที่ตกลงกับผู้ขอโดยตรงแล้ว และเลือกได้ว่าจะส่งอีเมลแจ้งผู้ขอหรือไม่

## เริ่มต้นใช้งาน

อ่านคู่มือฉบับเต็มที่ **[docs/DEPLOY.md](docs/DEPLOY.md)** สรุปสั้น ๆ คือ

ต้องเปิด Apps Script API ที่ <https://script.google.com/home/usersettings> ด้วยบัญชี pr@arts.tu.ac.th ก่อนหนึ่งครั้ง จากนั้น

```bash
./setup.sh          # macOS และ Linux
.\setup.ps1         # Windows (PowerShell)
```

ถ้าใช้ Terminal ไม่ได้ ให้คัดลอกไฟล์ในโฟลเดอร์ `dist/` ลงตัวแก้ไข Apps Script แทน (8 ไฟล์)
ดูขั้นตอนละเอียดที่ [docs/DEPLOY.md](docs/DEPLOY.md) หัวข้อ *วิธี ข*

จากนั้นเปิด <https://larts-design.mcorner-ap.workers.dev/setup> แล้วจับคู่กับเว็บแอป Apps Script
(ลิงก์ `/exec` + บัญชีผู้ดูแลระบบ) ระบบย้ายข้อมูลทั้งหมดมาที่ Cloudflare และตั้ง Apps Script เป็นระบบสำรองให้เอง
ดูหัวข้อ *ระบบหลักบน Cloudflare* ใน [docs/DEPLOY.md](docs/DEPLOY.md)

สคริปต์จะเข้าสู่ระบบ Google สร้างโปรเจกต์ Apps Script และอัปโหลดโค้ดให้ทั้งหมด
เหลือทำเองเพียง 2 อย่างที่ Google บังคับให้มีคนกดจริง

1. **Deploy** เป็น Web app แบบ *Execute as: Me* และ *Who has access: Anyone*
2. **เปิด Web app URL** — ระบบจะติดตั้งฐานข้อมูล โฟลเดอร์ และทริกเกอร์ให้เอง
   แล้วส่งรหัสติดตั้งไปที่อีเมล pr@arts.tu.ac.th เพื่อสร้างบัญชีผู้ดูแลระบบผ่านหน้าเว็บ

ตั้งค่า Claude API key ได้ที่หน้าเจ้าหน้าที่ → ตั้งค่า (ทางเลือก)

**อัปเดตเวอร์ชันภายหลัง** ใช้คำสั่งเดียว ไม่ต้องเข้าเบราว์เซอร์ และ URL ไม่เปลี่ยน

```bash
./deploy.sh         # ทดสอบ → อัปโหลด → ออกเวอร์ชันใหม่ทับ deployment เดิม
```

## ฐานข้อมูล (Google Sheets 12 ชีต)

| ชีต | เก็บอะไร |
|---|---|
| `Requests` | คำขอหนึ่งใบต่อหนึ่งแถว รวมสถานะ Design Brief และเวลาแต่ละขั้น |
| `Deliverables` | รายการชิ้นงานที่ขอ แยกตามประเภทสื่อและขนาด |
| `Attachments` | ทะเบียนไฟล์ทั้งไฟล์ต้นทางและไฟล์ส่งมอบ |
| `Revisions` | ข้อแก้ไขแต่ละรอบจากผู้ขอรับบริการ |
| `Timeline` | ประวัติทุกการเปลี่ยนแปลง ใช้ตรวจสอบย้อนหลังได้ |
| `Users` | บัญชีเจ้าหน้าที่ (รหัสผ่านเก็บเป็นค่าแฮชพร้อม salt) |
| `Settings` | ค่าตั้งค่าที่แก้ได้จากหน้าเว็บ |
| `Counters` | ตัวนับเลขที่คำขอ แยกตามปี พ.ศ. |
| `Replies` | ข้อมูลที่ผู้ขอส่งเพิ่มเมื่อเจ้าหน้าที่ขอข้อมูลเพิ่มเติม |
| `Feedback` | ผลประเมินความพึงพอใจหลังส่งมอบ (งานละหนึ่งแถว) |
| `Resources` | รายการในคลังไฟล์ CI (ไฟล์บน Drive หรือลิงก์) |
| `Designers` | รายชื่อผู้ออกแบบ สีประจำตัว ความถนัด และจำนวนงานที่รับได้พร้อมกัน |

ชีตใหม่สร้างให้เองเมื่อใช้งานครั้งแรก ระบบที่ติดตั้งไว้แล้วไม่ต้องทำอะไรเพิ่ม
งานที่ย้ายไปเก็บถาวรจะอยู่ในสเปรดชีตแยก `… — ข้อมูลเก็บถาวร` โครงสร้างชีตเหมือนกัน

## ความปลอดภัย

- รหัสผ่านเจ้าหน้าที่เก็บเป็นค่าแฮช HMAC-SHA256 วนซ้ำ 2,000 รอบ พร้อม salt รายบัญชีและกุญแจลับของระบบ
- Session ใช้ token ที่เซ็นด้วย HMAC มีอายุ 12 ชั่วโมง ปลอมแปลงไม่ได้ และตัดสิทธิ์ทันทีเมื่อปิดบัญชี
- ล็อกบัญชี 15 นาทีเมื่อกรอกรหัสผ่านผิดเกิน 5 ครั้ง
- ผู้ขอรับบริการเข้าถึงงานของตนเองได้ด้วยเลขที่คำขอคู่กับอีเมล หรือด้วย token ในลิงก์จากอีเมลเท่านั้น
- หน้าติดตามไม่เปิดเผยข้อมูลภายใน (Design Brief, บันทึกภายใน, ลิงก์โฟลเดอร์)
  แสดงผู้ออกแบบเฉพาะคนที่อยู่ในรายชื่อผู้ออกแบบ ชื่ออื่นที่เจ้าหน้าที่พิมพ์เองถือเป็นข้อมูลภายใน
- คิวงานบนหน้ายื่นคำขอแสดงเฉพาะชื่อโครงการ กำหนดใช้งาน สถานะ และผู้ออกแบบ
  ไม่มีชื่อ อีเมล เบอร์โทร หรือหน่วยงานของผู้ขอ และไม่มีอีเมลผู้ออกแบบ ปิดได้ที่หน้าตั้งค่า
- ข้อความจากผู้ใช้ถูก escape ก่อนแสดงผลทุกจุดทั้งในเว็บและในอีเมล
- พารามิเตอร์ใน URL ถูกกรองด้วยรายการอักขระที่อนุญาต และ JSON ที่ฝังในหน้าเว็บหลบอักขระ `< > &`
- จำกัดการยื่นคำขอ 5 รายการต่อชั่วโมงต่อหนึ่งอีเมล
- ทุกการเขียนที่ต้องออกเลขหรือเปลี่ยนสถานะทำภายใต้ `LockService` เพื่อกันข้อมูลชนกัน
- API key ของ Claude เก็บใน Script Properties ไม่ปรากฏในโค้ดหรือหน้าเว็บ
- ฟังก์ชันที่เรียกจากหน้าเว็บได้มีเฉพาะ `api*` (ตรวจสิทธิ์ทุกตัว) และฟังก์ชันระบบที่ปลอดภัย ชุดทดสอบบังคับรายการนี้ไว้
- Cloudflare กับ Apps Script คุยกันด้วยรหัสลับที่ออกตอนจับคู่ (ต้องใช้บัญชีผู้ดูแลระบบ)
  จับคู่ได้เฉพาะ deployment ของคณะ และไฟล์ที่อัปโหลดต้องมีใบรับที่เซ็นด้วยรหัสลับนี้

## การทดสอบ

```bash
npm test          # Apps Script 289 รายการ + Cloudflare 35 รายการ
```

ชุดทดสอบ Apps Script ครอบคลุม การติดตั้งระบบ การตรวจสอบข้อมูลแบบฟอร์ม การออกเลขที่งาน
การแนบไฟล์ การส่งอีเมล สิทธิ์การเข้าถึงหน้าติดตาม เส้นทางการเปลี่ยนสถานะ รอบการแก้ไข
การเรียก Claude API และการสำรองเมื่อ API ล้มเหลว งานเบื้องหลัง ระบบเข้าสู่ระบบ สถิติ
และการป้องกันการแทรกโค้ด — โดยจำลอง Google Apps Script ทั้งหมดจึงรันได้โดยไม่แตะระบบจริง

ชุดทดสอบ Cloudflare รัน Durable Object ตัวจริงบน SQLite ของ Node คู่กับ Apps Script ตัวจำลองผ่าน `doPost`
ตรวจว่าสำเนาสองฝั่งตรงกันทุกแถวหลังทุกขั้นตอน รวมถึง Google ล่มแล้วกลับมา และการสลับกลับไปใช้ Apps Script
